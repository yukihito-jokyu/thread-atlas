# L4-M5-S3: 復元時の現行正本と履歴・由来・Undo参照の整合条件

## 目的

一つの復元対象Sessionについて、FR-020の7対象が参照する現行正本を、有効なEvent／ChangeSet、訂正・再判断・業務上取消およびUndo結果と矛盾なく対応付ける。復元後に旧内容、取消前の結果またはUndo前の値を現行として誤採用せず、各現行値から旧内容と根拠会話へ追跡できるようにする。

履歴・由来・UndoはFR-020の追加復元対象ではなく、7対象の現行正本を確認する横断参照である。

## 共通前提

- 対象範囲は `L4-M5-S2` が閉包した一つの未完了Sessionだけである。Event、ChangeSet、旧内容、根拠会話およびUndo Relationの端点を別Sessionへ広げない。
- 7対象と論理正本の対応は `L4-M5-S1` を入力とする。状態、完了条件または履歴を第8対象や新たな正本にしない。
- Event、ChangeSet、訂正・再判断・業務上取消の新旧Relation、由来RelationおよびUndo Relationの型・Cardinality・生成規則は `L4-M3〜M4` を参照する。本書は復元時の採用整合だけを定める。

## 旧内容・由来・Undoの横断条件

- 訂正、再判断および業務上取消は、後続のEvent／ChangeSetとして旧内容との新旧Relationを持つ。旧内容は削除・上書きせず、現行正本と別に追跡可能とする。
- Undoは新Undo Event／ChangeSetと元対象ChangeSetのUndo Relationとして追跡する。復元時に採用する現行結果は、有効なUndo結果を含む現行正本と一致させるが、Undo可否、対象選択、依存閉包または適用そのものは再判定しない。
- 会話、ユーザー要求、AI提案、既存論理情報、ActorおよびRuleの根拠参照はEventを経由して追跡する。ChangeSetは起点会話や対象を直接結ばず、Eventの所属を確認する。
- 記録済みで当該現行値の追跡に必要な旧内容、根拠会話、Undo Relationまたは由来Relation（およびその端点）が欠落・矛盾・別Sessionを指す場合、推測で現行値を選ばず、本書の整合が成立したと扱わない。起点会話がないEventまたはUndo未実施だけでは不整合としない。

## 非混同と責務境界

- 現行／旧内容の採用整合は本書が所有するが、状態・遷移・完了可否・階層・現在地・復帰先の意味はL2、Actor・承認・GuardはL3が所有する。
- Undo可否、対象分類、原子性、依存閉包および適用後整合は `L4-M4` が所有する。訂正・再判断・業務上取消をUndo、またはUndoを通常の逆遷移として扱わない。
- 復元後のL2不変条件と未完了議論の通常進行再開は `L4-M5-S4` が所有する。本書は再開を実行・許可しない。
- Snapshot／Replay、復元順、現行値選択の実装、修復、DB・Transaction・Serialization・欠損補正および障害復旧はL8、提示はL5、操作・APIはL6、評価はL7が所有する。
