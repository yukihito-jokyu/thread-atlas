# L4-M4-S1: Undo可能対象・不可対象と非Undo変更の分類

## 目的と共通前提

`L4-M3`で定義した全ての有効なChangeSet種別を、Undo対象として**可能**、**条件付き**又は**不可**へ一意に分類する。ここでの分類は論理上の対象性だけを表す。選択したChangeSetを戻す計画の全適用／全拒否は`L4-M4-S2`、因果・参照依存を含む動的可否は`L4-M4-S3`、適用後の状態・履歴整合は`L4-M4-S4`が所有する。

`可能`は、この分類だけでは非Undo境界に該当せず、後続の計画対象にできることを表す。`条件付き`は、元のChangeSetを訂正・再判断・業務上取消と同一視せず、L2/L3の有効性及び後続Ownerの条件を満たす場合だけ計画対象にできることを表す。`不可`は、Undo計画の対象にしないことを表す。分類はActor、操作名、UI、API、Transaction、補償、保存方式を定めない。

## 分類Rule

| Rule ID | 規則 | 後続Owner・非導出事項 |
| --- | --- | --- |
| `L4-M4-S1-R-01` | `L4-M3-S1`のEvent対象であり、`L4-M3-S2`に従い1件以上のEventを持つChangeSetだけを分類対象にする。後掲の種別表は含まれるEventの被覆根拠であり、複合ChangeSetの分類は`R-05`で一意に決める。 | Eventの対象／対象外、ChangeSet境界・順序・因果はL4-M3が所有する。読取、失敗、禁止Guardによる拒否、no-opはChangeSetを作らず、Undo対象にもならない。 |
| `L4-M4-S1-R-02` | 通常の現行論理情報だけを追加・更新・解除したChangeSetは`可能`とする。ただし、この分類だけからUndo実行、部分的な逆変更、状態遷移又は権限充足を導かない。 | S2が単一又は連動の全適用／全拒否、S3が依存閉包、S4がL2/L3整合を定める。 |
| `L4-M4-S1-R-03` | Guard、Proposal判断、訂正・再判断・業務上取消又は会話の論理的訂正を含むChangeSetは`条件付き`とする。これらは意味上の後続変更であり、Undoの別名ではない。 | L2/L3の許可・Guard、S2の原子計画、S3の動的可否、S4の事後整合を満たす場合だけ後続のUndo計画へ渡せる。 |
| `L4-M4-S1-R-04` | 既にUndoの対象となったChangeSet及びUndo自体を記録するChangeSetは`不可`とする。会話原文又は履歴記録を消去・改変する要求・試行は、`L4-M3-S1`のEvent対象外であり、ChangeSetを作らない。 | Redo、時間制限、履歴の物理削除又は補償方式を追加しない。Undoの記録と旧Event・根拠会話の保持はS4が所有する。 |
| `L4-M4-S1-R-05` | 複数種別のEventを含むChangeSetは、`R-04`に該当するEventを一つでも含めば`不可`、それ以外で`R-03`に該当するEventを一つでも含めば`条件付き`、それ以外を`可能`とする。この優先順により、各分類対象のChangeSetは可能／条件付き／不可のちょうど一つへ属する。 | 同一ChangeSet内のEventを分割して戻す可否は決めない。S2の全適用／全拒否、S3の依存閉包、S4の事後整合を先取りしない。 |

| --- | --- | --- | --- |

| 状態軸値、完了条件・充足判定、Decision、通常Topicの保留又は対象外判断結果の通常更新 | 可能 | 現行論理情報の通常更新として`R-02`を適用する。決定済みと正常完了、対象外と削除、保留と中断を同一視しない。 | 状態語彙・完了判定・遷移はL2、Actor／承認はL3、現行RelationはL4-M2が所有する。Undoだけで正常完了、親復帰又は現在地変更を決めない。 |

| 理解停止Guard又は要確認の成立・維持・明示解除／解消を記録するChangeSet | 条件付き | 一時Guardを永続状態へ追加せず、対象文脈・明示解除又は明確化の関係を損なわない場合だけ`R-03`の対象にする。 | Guardの成立・維持・解除、曖昧入力はL3、状態・遷移はL2が所有する。Undoだけから通常進行、確定更新又はGuard解除を導かない。 |
| 発言本文の論理的訂正、通常Topicの訂正、再判断又は業務上取消を後続変更として記録するChangeSet | 条件付き | 訂正・再判断・業務上取消は旧Event／ChangeSetを削除・上書きしない後続変更である。新旧Relationと旧内容が保持され、Undoと混同しない場合だけ`R-03`の対象にする。 | 訂正の優先・適用はL3-M4-S2、提案再判断はL3-M2-S3、現行正本はL4-M2、旧内容RelationはL4-M3-S3が所有する。 |
| 既にUndo対象となり、Undo適用後の履歴Relationを持つ元ChangeSet | 不可 | 同じ元ChangeSetを再びUndo対象にせず、既Undo対象を新たなUndo、Redo又は履歴巻戻しとして扱わない。 | Undo後のライフサイクル整合・元対象とのRelationはS4が所有する。再び扱う必要があっても、後続の通常変更又は訂正経路をUndoへ読み替えない。 |
| Undo適用を記録する新しいChangeSet | 不可 | Undo自身は別のUndo対象にしない。これによりRedoを暗黙に導入しない。 | Undoを新Event／ChangeSetとして記録する方法と適用後整合はS4、実行権限はL3、操作はL6が所有する。 |

## 非Undo変更との分離

- 訂正、再判断及び業務上取消は、利用者の意図に基づく後続ChangeSetであり、過去のChangeSetを逆に適用するUndoではない。Undo分類を理由にこれらの意味、優先、許可又は現行値を変更しない。
- 会話原文、旧内容、Event、ChangeSet及び由来Relationの保持は、Undoの対象外である。保持された履歴を参照可能にすることは、表示・検索・保存の方式を定めない。
- 会話原文、旧Event／ChangeSet、旧内容、新旧Relation又は根拠会話を消去・改変する要求・試行は、`L4-M3-S1`のEvent対象外であり、Undo分類にもChangeSetにも入れない。発言本文の論理的訂正は、旧内容を保持する後続ChangeSetとして分類表の`条件付き`に従う。
- `不可`は失敗、禁止Guardによる拒否又はno-opを履歴上の新しい分類対象へ変える規則ではない。これらは`L4-M3-S1`の対象外のままとする。
- 本書はUndo実行のActorを定めず、L3の基準権限を参照するだけとする。操作名・呼出し・UI・API、Transaction、補償、保存・復元方式はそれぞれL6又はL8へ残す。

## 責務境界とTask固有Review

- S2は選択ChangeSet又は連動Undo計画の論理原子性と部分適用禁止、S3は因果・参照依存に基づく拒否又は連動、S4はUndo後のL2/L3整合、元対象Relation及び履歴非削除を所有する。
- L2は状態・遷移・不変条件、L3は実行権限・Guard、L4-M3はEvent・ChangeSet・因果・旧内容・由来、L4-M5は復元採用と整合、L5は表示、L6は操作、L7は受入、L8は物理設計を所有する。
- Redo、時間制限、物理Rollback、補償、履歴削除、保存形式を追加しない。
- [x] 全ChangeSet種別を可能／条件付き／不可へ一意に分類し、Rule IDを付与した。
- [x] 既Undo対象、Undo自身、会話原文、履歴記録と訂正・再判断・業務上取消をUndoから分離した。
- [x] 原子性、依存閉包、事後整合、Actor・操作・物理設計を後続Ownerへ残した。
