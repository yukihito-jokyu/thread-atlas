# L4-M3-S1: 論理変更Eventの構成要素と対象粒度

## 目的

議論Sessionの現行論理情報が意味上変更された事実を、1件の論理変更Eventとして識別するための共通辞書と、全ての可変対象／対象外の被覆を定める。

本書はEvent Sourcing、物理ID、時刻、保存形式、API、表示、操作主体または権限を定めない。状態・遷移・GuardはL2、Actor・承認・Ruleの意味はL3、複数Eventのまとまり・順序・因果はL4-M3-S2が所有する。

## Event辞書

| 項目 | 定義 | 境界 |
| --- | --- | --- |
| 論理Event ID | 一つの意味上の変更事実を他のEventから区別する論理参照。 | 物理ID型、採番、保存方式はL8が所有する。 |
| 対象Session | 変更対象が所属する一つの議論Session。 | Session境界と論理識別はL4-M1が所有する。 |
| 変更対象 | 変更前後を比較できる一つ以上のEntityまたはRelation。対象の種別と論理参照を記録する。 | Entity辞書・CardinalityはL4-M1〜M2が所有する。複数対象を一操作へ束ねる方法はS2が所有する。 |
| 変更種別 | 追加、更新、解除、関係設定、関係解除、現行結果の差替え、または論理上の取消を区別する分類。 | 各種別を許可するTrigger・Guard・状態効果はL2/L3が所有する。UndoはL4-M4と別概念である。 |
| 変更前／変更後 | 対象について意味上の比較に必要な前後の論理内容または関係。追加は変更前なし、解除は変更後なしを取り得る。 | 値の正しさ・現行判定・状態遷移はL2/L3が所有する。旧内容の保持・訂正関係はS3が所有する。 |
| Actor／Rule参照 | 変更を許可したActor区分またはRuleを参照する情報。 | Actor・承認・Ruleの定義はL3が所有し、本書は主体や権限を確定しない。 |
| 起点参照 | 変更の根拠となる発言、ターン、ユーザー要求、AI提案または既存の論理情報への参照。 | 起点会話から現行／旧結果までの双方向追跡はS4が所有する。 |

Eventは、同一Session内の対象に限る。一つの論理Eventが扱う対象粒度と、同じ操作に由来する複数Eventの所属・順序・因果はS2で定める。本書だけからEventの時刻順、因果、ChangeSet、履歴表示または復元順を導かない。

## 変更対象／対象外被覆表

| 分類 | Event対象となる論理変更 | Event対象外 | 後続Owner・非導出事項 |
| --- | --- | --- | --- |
| Session・会話 | Sessionの議論上の開始・終了に関する論理情報、発言本文の論理的訂正、発言・ターンと論点の関連を追加・変更・解除する場合。 | 発言本文の単なる読取り、表示の展開、物理受信や時刻取得。 | Entity・会話CardinalityはL4-M1、発言本文の旧版・訂正RelationはS3、会話との双方向由来はS4、物理記録はL8。 |
| Topicの文脈・構造 | Topic名（論点名）、背景、理由、決めたいこと、完了条件、未確認事項、親子・派生Relation、現在地または復帰先の現行論理情報を追加・変更・解除する場合。 | 地図のレイアウト、表示順、フォーカス選択だけの変更。 | Topicの論理同一性はL4-M1、意味・不変条件・改名を含む遷移の許可はL2/L3、ProjectionはL4-M1-S3、表示はL5。 |
| 状態・完了・Decision | 状態軸値、現行充足判定、Decision、保留または通常Topicの対象外判断結果を追加・変更・解除する場合。 | 判定の参照、表示だけの強調、完了可能性を計算するだけの読取り。 | 状態語彙・判定・遷移はL2、権限はL3、現行RelationはL4-M2。 |
| Proposalと3判断 | 未承認Proposal、必須情報、3判断の現行結果、生成Topicとの由来Relationを追加・変更・解除する場合。 | Proposal候補の閲覧、AIの未登録の思考、未承認Proposalを既存Topicとして扱うこと。 | 登録・判断・承認はL3-M2、現行RelationはL4-M2-S4、論点化の構造効果はL2。 |
| 一時Guard・明確化 | 理解停止Guardまたは要確認に関する、成立・維持・明示解除／解消として許可された論理情報を変更する場合。 | 再説明、確認要求、沈黙、時間経過、AI推測だけ。 | Guard・明確化の意味とActorはL3、状態・遷移はL2。一時Guardを永続状態へ追加しない。 |
| 訂正・再判断・業務上の取消 | 現行内容を後続の訂正、再判断または業務上の取消として変更する場合。 | Undo、履歴削除、過去内容の暗黙上書き。 | 新旧Event／ChangeSetのRelationと旧内容保持はS3、UndoはL4-M4。 |
| 操作・失敗・no-op | 許可された変更を実際に生じさせた場合だけEvent対象とする。 | 読取り、検証失敗、禁止Guardによる拒否、同一内容を再適用して論理情報が変化しないno-op。 | 操作/APIはL6、失敗・no-opのUI・ログ・実装表現はL8。禁止や失敗から状態・履歴を暗黙に変更しない。 |

## 整合条件

- Event対象の変更は、変更前後、対象Session、対象Entity／Relation、Actor／Rule参照および起点参照を意味上区別できる。情報を物理形式へどう記録するかは定めない。
- 一つの対象に複数の変更があり得ても、現行正本、旧内容、因果、順序およびChangeSetの境界を本書で推測しない。S2〜S4およびL4-M4〜M5の定義に従う。
- L2またはL3が禁止する遷移・更新を、Event辞書を理由に許可しない。Eventの存在は状態変更・承認・通常進行・正常完了を単独で意味しない。
- Eventは要件検証の証跡そのものではない。要件検証Traceabilityと受入評価はL7が所有する。

## 責務境界

- L2は状態語彙、完了判定、構造不変条件、Trigger・Guard・遷移を、L3はActor、承認、理解停止・提案・訂正Ruleを所有する。
- L4-M3-S2はChangeSet、論理順序、直接／派生原因、循環・孤立の禁止を、S3は訂正・再判断・業務上取消と旧内容保持を、S4は会話と現行／旧結果の双方向由来追跡を所有する。
- L4-M4はUndo対象と原子性、L4-M5は復元対象と整合を、L5は表示、L6は操作/API、L7は検証、L8は物理ID・時刻・Schema・保存・ログ・実装を所有する。
