# L1-M2-S1 AI新規提案の発見・スコープ識別シナリオ

## シナリオ情報

| 項目 | 内容 |
| --- | --- |
| Scenario ID | `L1-M2-S1`（Task IDと同一） |
| 名称 | AIが新規提案を発見し、現在スコープと区別して判断前まで引き渡す |
| 主Actor | AIエージェント |
| 支援Actor | ユーザー、UI |
| 目的 | AIが通常進行中に発見した新しい論点・観点・案を現在の議論へ暗黙に組み込まず、ユーザーが提案の由来と現在スコープとの差異を確認して判断できる状態にする |

## 事前条件

- `L1-M1-S2` が所有する一問一答の通常進行中である。
- 現在の論点と、ルートから現在地までの経路を確認できる。
- 現在の論点の背景、決めたいこと、完了条件、既知の残り論点、復帰先を確認できる。
- 今回の目的と、現時点でユーザー由来またはユーザー承認済みとして扱われているスコープを確認できる。
- AIエージェントとの対話、および現在の議論と新規提案を区別して参照できるUIを利用できる。
- 対象となる内容について、ユーザーによる提案判断はまだ行われていない。

## Trigger

AIエージェントが、現在の論点を進める過程で、現在の議論と関連するが現時点のスコープに含まれていない新しい論点・観点・案を発見する。

## 主要フロー

| # | Actor | 操作 | ユーザーが確認できる結果 |
| --- | --- | --- | --- |
| 1 | AIエージェント | 発見した内容について、どの論点から派生したか、何をきっかけに発見したかを特定する。 | 提案の派生元と発見理由を確認できる。 |
| 2 | AIエージェント | 発見した内容と今回の目的との関係、今の時点で議論する必要性、現在スコープに含まれる内容との差異を整理する。 | 目的にどう関係するか、なぜ今候補として示されたか、当初または承認済みのスコープから何が増えるのかを確認できる。 |
| 3 | AIエージェント | 発見した内容を既存の論点や決定事項へ直接組み込まず、AIが発見した新規提案として現在の議論から区別して反映する。 | 現在スコープと新しい候補を区別でき、AI由来の提案が既存要件や決定事項として扱われていないことを確認できる。 |
| 4 | UI | 新規提案の内容、派生元、発見理由、今回の目的との関係、今議論する必要性、現在スコープとの差異を参照可能にする。 | ユーザーは提案を判断するための情報を、現在の議論との関係を失わずに確認できる。 |
| 5 | AIエージェント、UI | 現在地と現在スコープを自動的に変更せず、対象の提案についてユーザー判断がまだ行われていないことを確認可能にする。 | 提案が未承認のままであり、ユーザー判断を経ずに現在の議論へ昇格していないことを確認できる。 |

## 現在スコープとの識別

本シナリオで新規提案として扱うのは、AIが新しく発見した内容のうち、現在の論点との関連はあるが、現時点でユーザー由来またはユーザー承認済みのスコープに含まれていないものとする。

発見した内容が次のいずれかに該当する場合は、本シナリオの新規提案として重複追加しない。

- 現在の議論構造に既に存在する論点である。
- ユーザーが提示済みまたは承認済みであり、現在スコープ内の既知の論点として扱われている。
- 現在の論点の既知の残り論点を言い換えただけで、スコープの追加を伴わない。

この場合は、既存の論点との同一性を確認できる状態を維持し、`L1-M1-S2` が所有する通常進行の既存経路に留まる。AIが既存内容か新規提案かを一意に識別できない場合も、現在スコープへ暗黙に組み込まず、差異を確認できるまで新しい論点として通常進行を開始しない。正式な同一性判定規則や、曖昧な場合の更新権限は本シナリオでは定義しない。

## 観測可能な成立結果

- AIが発見した新しい論点・観点・案の内容を確認できる。
- 提案がどの論点から派生し、AIがなぜ発見したかを確認できる。
- 提案と今回の目的との関係、および今議論する必要性を確認できる。
- 現在スコープに含まれる内容と新しい候補との差異を確認できる。
- AI由来の提案が、ユーザー由来またはユーザー承認済みの要件・論点・決定事項と区別されている。
- 現在地と現在スコープが、提案の発見だけでは変更されていない。
- ユーザー判断がまだ行われておらず、提案が現在の議論へ暗黙に昇格していないことを確認できる。
- 既存または承認済みの論点を新規提案として重複追加しない。

## 終了・ユーザー判断への引渡し

次の条件がすべて成立した時点で、本シナリオを終了する。

- 新規提案の内容、派生元、発見理由を参照できる。
- 今回の目的との関係、今議論する必要性、現在スコープとの差異を参照できる。
- 提案がAI由来の新しい候補として現在の議論から区別されている。
- 現在地と現在スコープが自動的に変更されていない。
- 対象の提案についてユーザー判断がまだ行われていない。

引渡し先は `L1-M2-S2` が所有する新規提案への判断入口とする。ユーザーが「今議論する」「後で議論する」「今回は対象外」のいずれかを選び、その判断後にどこへ進み、元の通常進行へどのように戻るかは `L1-M2-S2` が定義する。本シナリオでは、選択肢の提示後の判断、提案の論点化・昇格、保留または対象外としての確定、通常進行への復帰を行わない。

## 責務境界

- AIによる提案発見、派生元・理由・目的との関係・今扱う必要性・スコープ差異の確認、判断前の引渡しという、ユーザーから見える時系列だけを定義する。
- 「判断待ち」を正式な状態名として定義せず、ユーザー判断が未実施であるという観測可能な条件だけを扱う。正式な状態語彙、許可・禁止遷移、現在地変更、論点化の不変条件はL2へ残す。
- AIが自動追加できる範囲、AIとユーザーの更新権限、提案をユーザー承認必須とする範囲、曖昧な場合の扱いはL3へ残す。
- 提案・会話・議論状態・変更履歴のデータモデル、後日参照と保持方法はL4へ残す。
- 現在スコープと新規提案の具体的な画面配置・表現方式、差分の見せ方はL5へ残す。
- 新規提案追加操作の意味、Discussion Toolの責務、Tool API、JSON SchemaはL6以降へ残す。
- 新規提案に対する3つの判断、各判断後の継続先、後日の再判断経路はL1-M2-S2が所有する。本シナリオはユーザー判断前の引渡しまでを扱う。
- 通常進行の質問・回答・更新、AI認識の修正、論点の正常完了はL1-M1が所有する。本シナリオは `L1-M1-S2` から新規発見を受け取り、判断後の通常進行への復帰を定義しない。
- 新規提案の妥当性、優先度、採否、実現方法をAIだけで確定しない。
