# L1-M1-S3 AI認識のユーザー修正シナリオ

## シナリオ情報

| 項目 | 内容 |
| --- | --- |
| Scenario ID | `L1-M1-S3`（Task IDと同一） |
| 名称 | AIの認識差異を修正し、通常進行へ復帰する |
| 主Actor | ユーザー |
| 支援Actor | AIエージェント、UI |
| 目的 | 質問の前提またはAIが反映した議論状態に認識差異があるとき、ユーザーが正しい認識を示し、修正結果を確認してから一問一答の通常進行へ戻れるようにする |

## 事前条件

- `L1-M1-S2` が所有する一問一答の通常進行から引き渡されている。
- 現在の論点と、ルートから現在地までの経路を確認できる。
- AIエージェントが提示した質問の前提、または直前の回答に基づく議論状態の更新結果を確認できる。
- 更新結果から、根拠となった会話へ遡って参照できる。
- 論点の正常完了はまだ確定していない。

## Trigger

ユーザーが、AIエージェントの質問の前提または更新結果に、目的、論点名、親子関係、状態、AI提案の扱い、決定事項、回答解釈などの認識差異を見つけ、正しい認識を示す。

## 主要フロー

| # | Actor | 操作 | ユーザーが確認できる結果 |
| --- | --- | --- | --- |
| 1 | ユーザー | 認識が異なる対象と、正しい内容をAIエージェントへ伝える。 | どの質問の前提または更新結果を、どのように直したいかが会話として記録される。 |
| 2 | AIエージェント | 誤った認識のまま次の質問へ進まず、ユーザーが示した内容に基づいて必要な修正を議論状態へ反映する。 | 修正確認が終わるまで別の論点へ進まず、修正対象を維持していることを確認できる。 |
| 3 | UI | 修正された内容と、修正の根拠となったユーザーの発言を参照可能にする。 | 何が修正されたかを確認でき、修正結果から根拠会話へ遡れる。 |
| 4 | AIエージェント | 修正後の認識を、ユーザーが確認できる形で示す。 | ユーザーは自分が示した正しい内容と修正結果を照合できる。 |
| 5 | ユーザー | 修正後の認識に差異がないことを確認する。 | 修正が成立し、修正後の議論状態を通常進行の有効な状態として扱える。 |

## 修正が一致しない場合

ユーザーが修正後の認識にも差異を見つけた場合は、通常進行へ戻らず、追加で正しい内容を示す。AIエージェントは誤った認識のまま別の質問や論点へ進まず、主要フローの手順2から修正と確認を反復する。

ユーザーが示した内容だけでは修正対象または正しい内容を一意に把握できない場合は、AIエージェントが対象を明確にするための確認を一問だけ提示する。ユーザーの回答後も、修正結果に差異がないことを確認するまで通常進行へ戻らない。曖昧な発言を議論状態へ反映できる条件や更新権限は、本シナリオでは定義しない。

## 観測可能な成立結果

- ユーザーが、AIエージェントの質問の前提または更新結果にある認識差異と、正しい内容を示せる。
- 修正確認が終わるまで、誤った認識を前提とする次の質問や別の論点へ進まない。
- 論点名、親子関係、状態、AI提案の却下、決定事項を含む議論状態のうち、認識差異がある対象の修正結果を確認できる。
- 何が修正されたかを確認でき、修正結果から根拠となったユーザーの発言へ遡れる。
- 修正後の認識に差異が残る場合は、修正と確認を反復できる。
- ユーザーが修正結果に差異がないことを確認した後、修正後の有効な議論状態から一問一答の通常進行へ戻れる。

## 終了・通常進行への引渡し

次の条件がすべて成立した時点で、本シナリオを終了する。

- ユーザーが示した正しい内容に基づく修正結果を参照できる。
- 何が修正されたかを確認でき、修正結果から根拠となったユーザーの発言へ遡れる。
- ユーザーが、修正後の認識に差異がないことを確認している。
- 修正後の有効な議論状態と、ルートから現在の論点までの経路を参照できる。

引渡し先は `L1-M1-S2` が所有する通常進行Anchorとする。現在の論点の背景、決めたいこと、完了条件、既知の残り論点、復帰先を修正後の有効な議論状態として確認でき、AIの認識差異が示されておらず、論点の正常完了が確定していない状態で、次に確認する質問を一問だけ提示して通常進行へ戻る。

修正によって現在の論点が完了可能であることが示された場合は、通常進行Anchorへ戻った後、`L1-M1-S2` から `L1-M1-S4` の正常完了確認へ引き渡す。本シナリオ内では論点の正常完了または親論点への復帰を確定しない。

| FR-015 | AIが構築した議論構造について、論点名、親子関係、状態、提案、決定事項を含む認識差異をユーザーが修正できる。 |

## 責務境界

- 認識差異の発見、ユーザーによる正しい内容の提示、修正結果の確認、通常進行への復帰という、ユーザーから見える時系列だけを定義する。
- 論点や決定の正式な状態語彙、許可・禁止遷移、完了条件の再判定はL2へ残す。
- AIとユーザーの更新権限、ユーザー訂正の優先規則、曖昧な発言の確定更新条件はL3へ残す。
- 会話・議論状態・変更履歴のデータモデル、訂正とUndo・再判断・業務上の取消の関係、旧内容の保持単位はL4へ残す。
- 修正前後の差分、変更履歴、根拠会話の具体的な画面配置・表現方式はL5へ残す。
- 修正操作の意味、Discussion Toolの責務、Tool API、JSON SchemaはL6以降へ残す。
- AIが新しく発見した論点・観点・案を現在の議論へ追加する場合はL1-M2、ユーザーが理解停止または背景再説明を求める場合はL1-M3、ユーザーが議論の中断・再訪を求める場合はL1-M4へ引き渡す。
- 通常進行AnchorはL1-M1-S2、論点の正常完了・親復帰はL1-M1-S4が所有する。本シナリオは修正後の有効な議論状態をAnchorへ引き渡すところまでを扱う。
- ユーザーが過去に正しく成立した変更を後から取り消す操作や、合意済みの判断を新しい判断へ変更する操作は、AIの認識差異の修正として定義しない。

## Task固有Review

- Actor、事前条件、Trigger、操作、観測可能結果、終了・引渡し先を記述している。
- 認識差異の発見、正しい内容の提示、修正、修正結果の確認、通常進行への復帰がユーザーから見える時系列になっている。
- 修正確認が終わるまで、誤った認識のまま次の質問または別の論点へ進まない。
- 修正後も差異が残る場合の反復と、修正対象が曖昧な場合の一問だけの確認を記述している。
- FR-001、FR-013〜FR-015、FR-019、NFR-004との対応を追跡できる。
- `L1-M1-S2` からの入口と、同Taskが所有する通常進行Anchorへの復帰条件が一意である。
- 正常完了・親復帰、新規提案、理解停止、中断・再訪を本シナリオへ取り込んでいない。
- 状態遷移、権限、履歴モデル、表示方式、Tool API、受入基準、具体設計を追加していない。
- 業務上の取消・再判断・UndoをAI認識の修正と混同していない。
- MVP項目の追加・削除を行っていない。
- 本シナリオ本文に未解決の契約差異とTBDはない。
