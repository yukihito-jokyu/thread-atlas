# L1-M3-S2 背景再説明・理解未解消反復・通常進行復帰シナリオ

## シナリオ情報

| 項目 | 内容 |
| --- | --- |
| Scenario ID | `L1-M3-S2`（Task IDと同一） |
| 名称 | 背景を再確認し、理解の解消後に通常進行へ戻る |
| 主Actor | ユーザー |
| 支援Actor | AIエージェント、UI |
| 目的 | 理解不足の通知後または直接の再説明要求後に、現在の論点の背景を再確認し、理解が解消しない間は次論点へ進まず、L3が所有する解除条件の成立後に同じ論点・文脈から通常進行へ戻れるようにする。 |

## 入口と事前条件

本シナリオには、次の二つの入口がある。

| 入口 | Trigger | 入口時に確認できること |
| --- | --- | --- |
| A. 理解不足通知後 | `L1-M3-S1`から背景再説明へ引き渡される。 | 文章入力なしの理解不足通知後も、現在の論点、経路、背景、決めたいこと、完了条件、既知の残り論点、復帰先が保たれ、次論点が開始されていない。 |
| B. 直接再説明要求 | 通常進行中のユーザーが、現在の論点の背景再説明を求める。 | `L1-M1-S2`が所有する通常進行Anchorを参照でき、現在の論点とその文脈を確認できる。 |

入口Bの直接再説明要求だけでは、理解停止の成立または解除を確定しない。理解停止の成立・維持・解除とAI統制はL3が所有する。

両入口で、現在の論点とルートからの経路、背景、決めたいこと、完了条件、既知の残り論点、復帰先を確認できる。AI認識の修正、論点の正常完了、ユーザー都合の中断・再訪を処理中ではない。

## 主要フロー

| # | Actor | 操作 | ユーザーが確認できる結果 |
| --- | --- | --- | --- |
| 1 | AIエージェント、ユーザー | 入口Aでは、`L1-M3-S1`からの引渡しを受けてAIエージェントが現在の論点の背景再説明を開始する。入口Bでは、ユーザーが現在の論点の背景再説明を求める。 | どちらの入口でも、再説明の対象が現在の論点であることを確認できる。 |
| 2 | AIエージェント | 現在の論点について、なぜこの話をしているか、どの上位論点から派生したか、何を決めようとしているかを、一つの再説明として示す。 | 現在の論点の背景、派生元、決めたいことを再確認できる。 |
| 3 | UI | 現在の論点、経路、完了条件、既知の残り論点、復帰先を再説明と照合可能にする。 | 再説明が現在の論点・文脈に対応していることを確認できる。 |
| 4 | ユーザー | 再説明後に、理解が解消したか、まだ理解できないかを示す。 | 次の経路が理解状況に応じて分かれることを確認できる。 |

## 分岐

### A. 理解がまだ解消しない

ユーザーがまだ理解できないことを示した場合、AIエージェントは次の論点へ進む質問、別の論点への移動、論点の正常完了を行わない。現在の論点と文脈を維持し、主要フローの手順2から背景再説明と確認を反復する。

この反復では、再説明の具体的な戦略、文面、反復回数を定義しない。理解停止中の許可・禁止動作と統制はL3が所有する。

### B. 理解が解消し、通常進行へ戻る

ユーザーが理解の解消を示し、L3が所有する解除条件が成立した場合、AIエージェントは停止前と同じ現在の論点・文脈を確認する。確認対象は、現在の論点、ルートからの経路、背景、決めたいこと、完了条件、既知の残り論点、復帰先とする。

この確認後、`L1-M1-S2`が所有する通常進行Anchorへ引き渡す。通常進行では、同じ論点の有効な議論状態から、次に確認する質問を一問だけ提示する。解除条件の内容、成立の判定主体、解除操作は本シナリオで定義しない。

### C. 直接再説明要求後の通常進行

入口Bで再説明を受けたユーザーが、理解停止の成立を伴わずに通常進行の継続を求める場合、現在の論点・文脈を確認して`L1-M1-S2`が所有する通常進行Anchorへ戻る。直接再説明要求を理解停止の成立または解除として扱わない。

## 観測可能な成立結果

- 入口Aの理解不足通知後と、入口Bの直接再説明要求後を区別して背景再説明へ入れる。
- ユーザーはワンアクションで、現在の論点について、なぜこの話をしているか、どの上位論点から派生したか、何を決めようとしているかを再確認できる。
- 再説明中、現在の論点、経路、完了条件、既知の残り論点、復帰先を照合できる。
- 理解が未解消の場合は、次の論点の開始、別の論点への移動、論点の正常完了を行わず、再説明と確認を反復できる。
- L3が所有する解除条件の成立後は、停止前と同じ論点・文脈を確認して通常進行Anchorへ戻れる。
- 直接再説明要求だけでは、理解停止の成立または解除を確定しない。

## 終了・通常進行への引渡し

本シナリオは、次のいずれかで`L1-M1-S2`が所有する通常進行Anchorへ引き渡す。

- 入口Aで、理解の解消とL3が所有する解除条件の成立後に、停止前と同じ現在の論点・文脈を確認できた場合。
- 入口Bで、理解停止の成立を伴わない再説明後に、現在の論点・文脈を確認して通常進行の継続を求めた場合。

理解が未解消の場合は終了せず、分岐Aを反復する。AI認識の修正、論点の正常完了、ユーザー都合の中断・再訪、新規提案の判断は、それぞれの所有シナリオへ引き渡す。

## 責務境界

- 本シナリオは、二つの入口の区別、背景再説明、理解未解消時の反復、解除後または直接再説明後の通常進行Anchorへの復帰という利用者から見える時系列を定義する。
- 文章入力なしの理解不足通知と、通知前後の不変条件は`L1-M3-S1`が所有する。
- AI認識の修正は`L1-M1-S3`、論点の正常完了・親復帰は`L1-M1-S4`、ユーザー都合の中断・再訪はL1-M4、新規提案の判断はL1-M2が所有する。
- 論点の正式な状態語彙、遷移、現在地変更の許可・禁止はL2へ残す。
- 理解停止の成立・維持・解除条件、解除の主体、停止中のAI統制はL3へ残す。本シナリオは理解停止を永続状態として定義しない。
- 会話・通知・議論状態の保持単位と履歴はL4、具体的な表示方法はL5、論理操作・Tool APIはL6以降へ残す。

## Task固有Review

- S1経由の理解不足通知後と、通常進行からの直接再説明要求を区別している。
- 「なぜこの話をしているか／どこから派生したか／何を決めようとしているか」の再説明を確認できる。
- 理解未解消時は次論点へ進まず、再説明と確認を反復する。
- L3が所有する解除条件の成立後に、停止前と同じ論点・文脈を確認して通常進行Anchorへ戻る。
- 直接再説明要求だけで理解停止の成立または解除を確定していない。
- L1-M3理解支援ループGateの全経路へ入力を提供し、L2・L3・L5の責務を混入していない。
- 状態遷移、権限、データモデル、表示方式、Tool API、受入基準、具体設計を追加していない。
