# L1-M4-S2 中断論点の経緯確認・再訪シナリオ

## シナリオ情報

| 項目 | 内容 |
| --- | --- |
| Scenario ID | `L1-M4-S2`（Task IDと同一） |
| 名称 | 中断した論点の経緯を確認し、通常進行を再開する |
| 主Actor | ユーザー |
| 支援Actor | AIエージェント、UI |
| 目的 | 同一セッション内で中断した論点について、再訪前に必要な経緯を確認し、途中内容を失わずにその論点の通常進行へ戻れるようにする。 |

## 事前条件

- `L1-M4-S1`により、未完了の下位論点を正常完了にせず、親論点の通常進行へ戻っている。
- 同一セッション内で、中断した論点と親論点との関係を確認できる。
- 中断した論点について、派生元、中断位置、中断前の内容、関連する決定・保留・構造変化を確認できる。
- アプリ終了後のセッション復元、AI認識の修正、論点の正常完了を処理中ではない。

## Trigger

ユーザーが、同一セッション内で中断した論点を再び扱うことを選ぶ。

## 主要フロー

| # | Actor | 操作 | ユーザーが確認できる結果 |
| --- | --- | --- | --- |
| 1 | ユーザー | 中断した論点の再訪を選ぶ。 | 再訪対象が、以前中断した未完了の論点であることを確認できる。 |
| 2 | AIエージェント、UI | 再訪前に、論点の派生元、中断位置、中断前の内容、関連する決定・保留・構造変化を照合可能にする。 | どの親論点から、どこで、何を残して中断したかを確認できる。 |
| 3 | ユーザー | 経緯を確認して、当該論点の議論を再開することを選ぶ。 | 中断前の途中内容を失わずに再開する対象を確認できる。 |
| 4 | AIエージェント | `L1-M1-S2`が所有する通常進行Anchorで、再訪した論点について次に確認する質問を一問だけ提示する。 | 中断前の内容を引き継いで、一問一答の通常進行を再開できる。 |

## 観測可能な成立結果

- 中断した論点の派生元、中断位置、中断前の内容、関連する決定・保留・構造変化を再訪前に確認できる。
- 再訪は同一セッション内の中断論点を対象とし、アプリ終了後の復元とは区別できる。
- 中断前の途中内容を失わず、再訪した論点の通常進行を再開できる。
- 再訪によって論点の正常完了、決定、構造修正を暗黙に確定しない。

## 終了・通常進行への引渡し

次の条件がすべて成立した時点で、本シナリオを終了し、再訪した論点について`L1-M1-S2`が所有する通常進行Anchorへ引き渡す。

- 再訪対象が中断した論点であることを確認できる。
- 派生元、中断位置、中断前の内容、関連する決定・保留・構造変化を確認できる。
- 中断前の途中内容を失わず、現在の論点・経路・背景・決めたいこと・完了条件・既知の残り論点・復帰先を確認できる。

再訪しない場合は親論点の通常進行を継続する。再訪後にAI認識の修正、正常完了、理解停止、新規提案、中断が必要になった場合は、それぞれの所有シナリオへ引き渡す。

## 責務境界

- 本シナリオは、中断論点の経緯確認、再訪選択、通常進行Anchorへの復帰という利用者から見える時系列だけを定義する。
- 中断時の親論点継続は`L1-M4-S1`、アプリ終了後のセッション復元・再開は`L1-M4-S3`、正常完了・親復帰は`L1-M1-S4`が所有する。
- 論点の正式な状態・遷移はL2、履歴Event、Undo・復元粒度はL4、提示方法はL5、論理操作・Tool APIはL6以降へ残す。
- 再訪で必要になる構造修正は`L1-M1-S3`などの既存経路が所有する。

## Task固有Review

- S1からの中断論点Anchorと、通常進行Anchorへの復帰が一意である。
- 派生元、中断位置、中断前の内容、関連する決定・保留・構造変化を確認できる。
- 同一セッション内の再訪と、アプリ終了後の復元を混同していない。
- 履歴モデル、Undo、復元、表示、状態遷移、構造修正を先取りしていない。
