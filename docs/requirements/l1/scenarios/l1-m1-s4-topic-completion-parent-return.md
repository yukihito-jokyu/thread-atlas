# L1-M1-S4 論点の正常完了・親復帰シナリオ

## シナリオ情報

| 項目 | 内容 |
| --- | --- |
| Scenario ID | `L1-M1-S4`（Task IDと同一） |
| 名称 | 結果を確認して論点を正常完了し、親論点へ復帰する |
| 主Actor | ユーザー |
| 支援Actor | AIエージェント、UI |
| 目的 | 現在の論点で得られた結果を確認し、論点の正常完了と親論点への復帰を確認して、既知の次論点または上位フローへ進めるようにする |

## 事前条件

- `L1-M1-S2` が所有する一問一答の通常進行から、現在の論点が完了可能であるとして引き渡されている。
- 現在の論点と、ルートから現在地までの経路を確認できる。
- 現在の論点の背景、決めたいこと、現行の完了条件、決定事項、既知の残り論点、完了後の復帰先を確認できる。
- 直前までの回答に基づく更新結果と、その根拠となった会話を参照できる。
- ユーザー都合による中断、理解停止、AIの認識差異への対応中ではない。

## Trigger

現在の論点について、直前までの更新結果から完了可能であることが示され、結果と完了後の行き先を確認する段階へ進む。

## 主要フロー

| # | Actor | 操作 | ユーザーが確認できる結果 |
| --- | --- | --- | --- |
| 1 | AIエージェント | 現在の論点で得られた結果を、現行の完了条件、成立した決定事項、既知の残り論点と対応付けて示す。 | 何が決まり、どの完了条件に対応し、現在の論点を完了可能とする結果が何かを確認できる。 |
| 2 | UI | 完了対象の論点、完了として反映される内容、根拠となった会話、予定されている親論点への復帰先を参照可能にする。 | ユーザーは論点を完了する前に、結果、根拠、変更内容、完了後の行き先を照合できる。 |

## 結果確認で差異または不足が見つかった場合

手順3の結果照合で認識差異または完了条件に対する不足が明らかになった場合は、本シナリオの入口条件が成立していないものとして論点を完了しない。`L1-M1-S2` が所有する更新結果の確認と既存の分岐に留まり、認識差異がある場合は同Taskから `L1-M1-S3` へ、不足がある場合は同Taskの通常進行Anchorへ進む。本シナリオから新しい引渡し経路は定義しない。

`L1-M1-S2` の既存経路で差異または不足が解消され、再び完了可能として本シナリオへ引き渡された場合は、更新後の結果を改めて確認する。

## 親復帰後の引渡し

### A. 既知の次論点へ進む

復帰した親論点に、現在のスコープ内で既に存在する次論点がある場合は、その論点を次の現在地として扱う。次論点の背景、決めたいこと、完了条件、親論点との関係、完了後の復帰先をユーザーが確認できる状態で、`L1-M1-S2` の通常進行Anchorへ引き渡す。AIエージェントは次論点について一問だけ質問する。

AIが新しく発見した論点・観点・案をこの経路で暗黙に次論点とすることはせず、L1-M2が所有する新規提案の判断へ引き渡す。

### B. 既知の次論点がない

復帰した親論点に既知の次論点がない場合は、親論点を現在地として維持し、その結果と既知の残り論点を確認できる状態で上位フローへ引き渡す。本シナリオ内では、親論点自体の完了可否や、さらに上位へ復帰するための正式な判定規則を定義しない。

### C. 完了対象がルート論点である

完了対象に親論点がない場合は、架空の親論点や復帰先を生成しない。ルート論点完了後の正式な規則はL2へ残し、本シナリオでは、完了した結果と親への復帰がないことをユーザーが確認できる上位フローへの引渡しだけを扱う。

## 観測可能な成立結果

- 正常完了の前に、現在の論点で得られた結果、現行の完了条件、成立した決定事項、既知の残り論点を照合できる。
- 完了として反映される内容と、その根拠となった会話を確認できる。
- 結果の認識差異や不足が明らかになった場合は、現在の論点を完了せず、`L1-M1-S2` が所有する既存の分岐に留まれる。
- 正常完了した論点と完了結果を、親子関係の中で引き続き参照できる。
- 親を持つ論点の正常完了後は、現在地が既に関連付けられていた親論点へ戻り、復帰後の経路を確認できる。
- 復帰した親論点の文脈に、完了した子論点の結果が引き継がれたことを確認できる。
- 既知の次論点がある場合は、その背景、完了条件、復帰先を確認してから一問一答へ進める。
- 既知の次論点がない場合は親論点の上位フローへ、親を持たない場合は架空の復帰先を作らずルート完了後の上位フローへ引き渡せる。

## 終了条件

次の条件がすべて成立した時点で、本シナリオを終了する。

- 現在の論点で得られた結果と、完了として反映された内容を参照できる。
- 完了した論点と、その根拠となった会話を参照できる。
- 親を持つ場合は、復帰後の親論点が現在地となり、ルートから現在地までの経路と子論点から引き継いだ結果を参照できる。
- 既知の次論点、親論点の上位フロー、またはルート完了後の上位フローのいずれか一つへ引き渡されている。

## 責務境界

- 結果確認、正常完了、親復帰、既知の次論点または上位フローへの引渡しという、ユーザーから見える時系列だけを定義する。
- 完了条件の生成・変更・充足判定、正式な状態語彙、許可・禁止遷移、親復帰・ルート完了の階層不変条件はL2へ残す。
- AIとユーザーの完了権限、確認・承認の要否、Guard、曖昧な発言の扱いはL3へ残す。主要フローのActor表記は実行権限を割り当てず、L3で確定する条件の成立を前提とする。
- 会話・議論状態・変更履歴・トレーサビリティのデータモデル、正常完了と親復帰をまとめる更新単位はL4へ残す。
- 完了差分、完了した論点、現在地、経路、決定事項、根拠会話の具体的な画面配置・表現方式はL5へ残す。
- 正常完了・親復帰操作の意味、Discussion Toolの責務、Tool API、JSON Schema、失敗時の整合処理はL6以降へ残す。
- 新規提案とユーザーの判断はL1-M2、理解停止と背景再確認はL1-M3、ユーザー都合の中断・再訪・セッション復元はL1-M4が所有する。
- 本シナリオは正常完了だけを扱い、未完了のまま親へ戻る経路や、後日の再訪・再開を取り込まない。
- 既知の次論点への通常進行はL1-M1-S2へ引き渡し、新しい論点を暗黙に追加しない。
