# L5-M4-S1: 履歴項目の共通提示分類・項目要件

## 目的

有効なChangeSet及び含まれるEventについて、何が誰又はどのRuleによりどう変化したかを、提示・要約・非提示の根拠と共通項目で確認できる条件を定める。

## 種別の提示分類

| Event／ChangeSet種別 | 提示分類 | 提示条件 | 確認する対象・変更内容 | 導かないこと |
| --- | --- | --- | --- | --- |
| Sessionの論理開始・終了、会話の論理的訂正、会話と論点の関連変更 | 要約 | 対象Session・会話又は関連と、開始・終了・訂正・追加・解除の種別を確認可能にする。 | 会話の読取、物理受信又は時刻取得を履歴項目化しない。 |
| Topicの追加・更新・改名、親子・派生Relation、現在地・復帰先の変更 | 提示 | 変更対象と構造・文脈・現在地又は復帰先の変更を確認可能にする。 | 表示上の並びから構造・由来を推測しない。 |
| 状態、完了条件・充足判定・完了、Decision、保留・対象外の変更 | 提示 | 対象と現行変更内容を確認可能にする。 | 決定済みを完了、保留を中断、対象外を却下と同一視しない。 |
| Proposal登録、三判断、論点化後の由来・スコープ変更 | 提示 | 対象と判断・追加由来・スコープ変更を確認可能にする。 | 未承認Proposalを通常Topic、Decision又は現スコープ内へ暗黙昇格しない。 |
| 訂正、再判断、業務上の取消 | 要約 | 変更対象と、訂正・再判断・取消という変更種別を確認可能にする。 | 現行／旧結果、理由、優先関係又はUndo可否を決めない。 |
| 理解停止Guardの成立・維持・明示解除 | 要約 | 対象現在Topic・通知時文脈と、Guardに関する変更を確認可能にする。 | Guardを永続状態、通常進行開始又は暗黙解除として扱わない。 |
| 読取、失敗、Guard拒否、no-op | 非提示 | 履歴の論理変更を生じさせない事実として区別する。 | Event又はChangeSet、変更前後又は成功した更新を推測生成しない。 |

ChangeSetは含有する有効Eventの分類を根拠に、提示を一つでも含む場合は提示、提示を含まず要約を一つでも含む場合は要約として扱う。読取・失敗・Guard拒否・no-opはL4の論理変更Event及びChangeSetを生成しないため、非提示事実からChangeSetを推測生成しない。

## 共通履歴項目

| 項目 | 確認できる条件 | 導かないこと |
| --- | --- | --- |
| 変更種別・対象 | 上表の種別と、Eventが参照する既存Entity又はRelationを確認できる。 | Entityの新規種別、Cardinality又は正本を定義しない。 |
| Actor／Rule | 記録済みのActor又はRule参照を確認できる。不在を推測補完しない。 | Actorの権限・承認又はRuleのGuardを決めない。 |
| 変更前後・差分 | 既存Event／ChangeSetが保持する前後内容又は差分を確認できる。 | 差分方式、訂正・再判断・Undoの現行／旧判定を決めない。 |
| 論理順序・発生時点 | L4が保持する論理順序と、L8が記録した発生時点を区別して確認できる。 | 時刻精度、並び替え、会話順との同一視又は物理実行順を導かない。 |

## 整合条件と責務境界

- 提示対象はL4の有効なEvent／ChangeSetを根拠に確認する。正本、因果・順序Relation、Event所属、旧内容及び履歴保持はL4が所有する。
- 訂正・再判断・業務取消・Undoの現行／旧結果と理由はS2、根拠会話への由来はS3が所有する。本書は共通分類だけを定める。
- 状態・遷移はL2、Actor・承認・GuardはL3、検索・Undo実行はL6、時刻形式・並び・通知・具体履歴UIはL8、受入はL7が所有する。
