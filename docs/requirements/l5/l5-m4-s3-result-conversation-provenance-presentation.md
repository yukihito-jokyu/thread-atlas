# L5-M4-S3: 結果から根拠会話への由来提示要件

## 目的

Topic、Decision、Proposal及び現行／旧結果について、記録済みの由来Relationを介して根拠会話を確認できる条件と、複数根拠・根拠不存在・利用不能を誤認しない条件を定める。

## 由来対応表

| 結果 | 根拠会話を確認する経路 | 複数根拠・不存在・利用不能の扱い | 導かないこと |
| --- | --- | --- | --- |
| 現行Topic | 現行Topicから、L4の根拠Eventを経て、そのEventが起点参照する発言又はターンを確認する。所属ChangeSetはEventの所属として併記できる。 | 根拠Event又は起点会話が`0..N`件なら、記録済みの全件を区別する。0件は記録済みの根拠会話参照がない結果として示し、不在又は未記録の理由を推測しない。利用不能な会話は利用不能として区別する。 | 親子、派生、現在地、状態、完了又は表示順を由来から導かない。 |
| 現行Decision・保留／対象外の判断結果 | 現行結果から根拠Event及びその起点会話を確認する。 | 複数の根拠は一つの理由へ集約せず、記録済み参照が0件又は利用不能であっても判断の不存在又は無効として扱わない。 | 判断の意味、優先、状態効果、再判断又はスコープ変更を導かない。 |
| 未承認Proposal・3判断・生成Topic由来 | Proposal、現行判断又は生成Topic由来から根拠Event及び起点会話を確認する。 | Proposalごとの必須情報や元Topic由来と、根拠会話を同一視しない。複数根拠、記録済み参照が0件及び利用不能を区別する。 | Proposalを通常Topic、Decision又は現スコープ内へ暗黙昇格しない。 |
| 旧結果・訂正・再判断・業務上取消・Undo前後 | 現行又は旧結果から、L4の新旧Relationで結ばれた根拠Event及びその起点会話を確認する。 | 訂正・再判断・取消・Undoの各Eventが持つ複数根拠を区別する。記録済み参照が0件又は利用不能から、現行結果・旧結果・理由を推測しない。 | 新旧の優先、現行正本の選択、Undo可否又は履歴削除を導かない。 |

## 共通条件

- 結果から会話へは「結果 → 根拠Event → Eventの起点発言又はターン」とたどり、ChangeSetはEventの一意な所属を確認するだけで、結果又は会話を直接結ばない。
- 根拠会話、Actor又はRuleの記録済み参照が0件の場合は参照なしと示し、その理由（不存在・未記録等）を推測しない。記録済みでも利用できない場合は利用不能として別に区別し、いずれも別の会話、時系列、表示近接又はAI推測で補完しない。
- 本書は結果から根拠会話への提示条件だけを定める。会話から全影響結果への逆引き、検索、移動又はリンク方式は要求しない。

## 責務境界

- 由来Relation、Event、ChangeSet、Actor／Rule参照、同一Session制約及びCardinalityはL4が所有する。現行正本はL4-M2、旧内容・新旧RelationはL4-M3、Undo RelationはL4-M4が所有する。
- 状態・遷移・構造はL2、Actor・承認・GuardはL3、例外変更の現行／旧結果と理由の提示はS2、検索・操作はL6、具体表示・リンク・利用不能の表現はL8、受入はL7が所有する。
