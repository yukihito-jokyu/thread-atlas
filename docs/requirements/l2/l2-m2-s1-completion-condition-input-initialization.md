# L2-M2-S1: 完了条件の意味上の入力・初期設定規則

## 目的

各論点について「何が決まれば終了するか」を意味上明確にするため、完了条件に用いる入力、適用範囲、必須性、設定時点、条件数および条件なし例外を定める。

本書は完了条件を設定できる状態を定める。条件の生成・変更主体、承認、充足判定、状態遷移、文面・形式、保存方式および試験方法は確定しない。

## 完了条件の意味上の入力

完了条件は、少なくとも次の入力との関係を確認できるものとする。

| 入力 | 完了条件における意味 |
| --- | --- |
| 背景 | なぜこの論点が生まれ、何を解消するために扱うかを示す。完了後に議論の理由を失わない。 |
| 決めたいこと | この論点で確認または選択したい到達点を示す。完了条件は、単に会話が続いたことではなく、この到達点との関係を確認できる。 |
| 未確認事項 | 到達点に対して残る不明点・確認事項を示す。完了条件は、未確認事項がどのような扱いになれば終了を検討できるかを確認できる。 |

完了条件は、論点の現スコープ、確認済みの決定事項および未確認事項を根拠に意味上評価可能でなければならない。背景と決めたいことは、条件を設定する理由および到達点を説明する入力として保持する。

入力が未評価・未記録の場合、AIの推測で内容を補わない。内容の生成・更新、入力を誰が確認するかは L3、入力の保持・履歴は L4 が扱う。

## 適用範囲と必須性

| 対象 | 規則 |
| --- | --- |
| ルート論点 | 通常の議論を開始する前に完了条件を設定する。ルートであることだけを理由に条件を省略しない。 |
| 下位論点 | 下位論点へ入る前に完了条件を設定する。背景、決めたいこと、未確認事項との関係を親論点から暗黙に流用しない。 |
| 新規提案 | 新規提案の発見・判断段階には、通常論点の完了条件を設定しない。承認後に通常論点として扱う場合の設定時点・許可条件は後続Ownerが扱う。 |
| 対象外 | 現スコープで扱わない対象について、通常進行の完了条件を設定しない。再対象化の条件は L2-M4 と L3 が扱う。 |

通常論点には完了条件を必須とする。ただし、次節の条件なし例外に該当する場合だけ、明示的に条件集合を持たないことを認める。

## 設定時点と条件数

- ルート論点は、通常進行を開始する前に設定する。
- 下位論点は、その下位論点へ入る前に設定する。親論点の完了、親への復帰、現在地の変更はこの規則から導かない。
- 完了条件は一つまたは複数を設定できる。一つの条件だけで十分か、複数条件をどう集約するか、条件相互の充足判定は L2-M2-S3 が扱う。
- すでに設定された条件の変更・有効期間・再判定は L2-M2-S2 が扱う。

## 条件なし例外

条件なしを認めるのは、論点の目的が「決定や検討を行うこと」ではなく、既知の内容を確認して通常進行へ戻すことだけであり、背景・決めたいこと・未確認事項のいずれにも新たな検討対象がない場合に限る。

条件なし例外の論点も通常完了対象にできる。ただし、既知内容の確認が完了し、新たな検討対象がないことを意味上確認できる場合に限る。条件がないことだけを理由に自動的に充足、完了、決定済み、または親への復帰としない。例外の該当判定、正常完了可否、遷移は後続Ownerが扱う。

## 後続境界

- 条件の変更、変更後の旧判定非流用、再判定は L2-M2-S2、充足・未充足・判断不能および正常完了可否は L2-M2-S3 が扱う。
- 完了・未完了を状態語彙へ追加せず、状態軸・組合せは L2-M1 の確定成果物を参照する。
- Trigger、遷移、親復帰は L2-M4、Actor・生成・承認は L3、Entity・履歴・保存は L4/L8、表示は L5、操作/APIは L6、測定・試験は L7 が扱う。
