# L6-M3-S3: 変更履歴・現行／旧結果・根拠会話照会Capability契約

## 目的

同一Sessionの会話履歴、論理変更履歴、現行／旧結果及び根拠会話を、記録済みのEvent・ChangeSet・Relationを介して照会するCapabilityを定める。

## 対象と共通契約

- 対象は同一Sessionの会話履歴、論理変更Event、ChangeSet、現行又は旧のTopic・Decision・Proposal・判断結果及びUndo結果とする。任意Topic・部分木・全体の現行構造照会はL6-M3-S2が、表示コンテキストはS4が所有する。
- 現行結果はL4-M2が保持する記録済み現行正本Relationを参照して取得する。後続Event／ChangeSet、新旧Relation、論理順序又は発生時点だけから現行を推測選択しない。
- 根拠会話は「結果 → 根拠Event → Eventの起点発言又はターン」の記録済み経路で照会する。ChangeSetはEventの一意な所属を確認するだけで、会話又は結果を直接結ばない。
- 会話・履歴・根拠の照会だけでは、状態、Decision、Proposal判断、現在地、構造、完了、スコープ、Actor、承認、Guard又はUndoを変更しない。検索、索引、Pagination、逆引き、リンク、API及びUIの方式はL8が所有する。

## 照会対象と取得契約

| 照会対象 | 照会できる記録済み情報 | 照会結果から導かないこと |
| --- | --- | --- |
| Session会話履歴 | 発言、ターン、同一Session内の論理順序及び各Eventの起点参照 | 会話順から変更順、親子、派生、状態、Decision又は現在地を推測すること |
| 変更履歴 | Eventの変更種別・対象・Actor／Rule参照、所属ChangeSet、論理順序及び直接／派生原因Relation | Event又はChangeSetを実行・追加・削除すること、物理時刻、Transaction又は保存方式を定めること |
| 現行／旧結果 | L4-M2の現行正本Relation、L4-M3の新旧Relationで区別された訂正・再判断・業務上取消の前後結果 | 現行結果の暗黙選択、旧内容の削除、訂正・再判断・取消からの状態遷移又はスコープ変更 |
| Undo結果 | 対象ChangeSet、適用済み・拒否・適用不可の記録済み結果、Undo後の現行正本又は既存現行の保持、記録済み理由 | Undoを訂正・再判断・業務上取消、逆遷移、物理Rollback、Redo又は履歴削除として扱うこと |
| 根拠会話 | Topic、Decision、Proposal、現行／旧結果又はUndo前後からたどる根拠Eventと起点発言／ターン、Actor／Rule参照 | 根拠会話の不存在・未記録理由、Actor又はRuleを推測すること、会話から全影響結果を逆引き必須化すること |

## 現行／旧結果と根拠会話の整合条件

- 訂正、再判断及び業務上取消は後続の論理変更として、Undoとは別に照会する。旧Event、旧ChangeSet、旧内容及び根拠会話を削除せず、各結果の前後を新旧Relationに従って区別する。
- 一つの結果が持つ記録済み根拠Event、起点会話、Actor又はRuleは`0..N`件として区別する。記録済み参照が0件なら参照なしとし、その理由（不存在・未記録等）を推測しない。記録済みでも利用不能な参照は別に区別する。
- EventがChangeSetに所属しない孤立を作らず、有効な論理変更Eventは記録済みの影響結果とのRelationを参照できる。読取、失敗及びno-opは履歴照会の対象となる論理変更を新たに生成しない。
- 根拠会話への照会は、表示上の近接、要約又はAIの会話解釈でRelationを補完しない。会話を起点に持たない正当なEventについても、会話由来を作らない。

## 責務境界

- L4はEvent、ChangeSet、論理順序、因果、新旧Relation、現行正本、旧内容、由来Relation及びUndo Relationを所有する。本書は照会経路を定めるだけで、履歴又は正本を複製しない。
- L5は履歴項目、現行／旧結果、理由及び根拠会話の提示・要約・優先を所有する。本書は照会可能な論理結果を定め、表示順又は集約を定めない。
- L2/L3は状態・遷移・構造、Actor・承認・Guard及び訂正・再判断の意味を所有する。L6-M3-S4は選択・会話参照等の表示コンテキスト、S5は取得結果の意味分類を所有する。
- L8はQuery・検索・索引・Pagination・API・UI、発生時点の記録、保存、Transaction及び障害処理を所有する。

## Task固有Review

- Session会話、Event・ChangeSet、現行／旧結果及び根拠会話を、記録済みRelationを介して非混同で照会対象化した。
- 現行正本からの現行取得と、新旧Relationに基づく旧結果の取得を分離し、履歴順だけで現行を選択しないことを確認した。
- 複数根拠、参照なし及び利用不能を分離し、欠落・近接・会話解釈からの補完を禁止した。
