# L6-M5-S2: Codex初期接続の論理プロファイル、制約・前提及びL8確認項目

## 目的

Codexを初期接続対象として扱う際に、L6-M5-S1のAI非依存Capability基準を満たすための論理適合条件を定める。これはCodex SDK、Model、Tool登録又は接続方式を選定する仕様ではない。未確認の固有挙動を製品要件へ混入させず、仮定、未検証事項及びL8で確認する設計事項を区別する。

## 会話生成と正本操作の分離

- Codexは質問、再説明、要約、要求候補又は結果説明を生成できる論理提供者である。これらはDiscussion Toolによる検証済みの正本操作と同一ではない。
- 正本の参照、更新、現行値の選択、履歴・Undoの整合及び更新結果の意味区分は、L2〜L4及びDiscussion Toolの既存契約に従う。Codexの会話記憶、推定又は一度の応答を正本の代替にしない。
- UIはCodexの出力を表示できるが、表示・選択・入力のローカル状態だけから正本、Actor承認、現在地又は同期完了を確定しない。
- Codexが利用不能でも、L6-M5-S1でUI又はDiscussion Toolが代替提供者となるCapabilityはその正規経路で扱う。代替がない必須又はTrigger中の条件付きCapabilityは、当該操作を開始又は成功扱いにしない。

## Codex前提の分類とL8確認事項

| Codexに関する記述 | 区分 | 本書で確定する論理上の扱い | L8で確認・設計する事項 |
| --- | --- | --- | --- |
| CodexがTool要求候補を会話生成から分離して出せる | 仮定 | 要求候補は正規Tool経路へ渡すまで正本を変更しない | Model／SDKのTool Calling能力、Tool登録、出力形式、不正形式時の非実行。 |
| CodexがToolの意味結果を受け取り会話を継続・終了できる | 仮定 | 成功・拒否・失敗・結果不明の意味区分はTool結果を基準にする | 応答→Call→結果→継続／終了のLoop、相関、Provider結果のM3契約写像。 |
| Codexが最新正本参照を必要時に再取得できる | 未検証 | 古い文脈だけでは更新・再開・同期済みを確定しない | Context Assembly、Snapshot／Version、再取得、差異検出、再同期方式。 |
| Codexが重複要求を識別又は相関情報を保持できる | 未検証 | 重複防止はDiscussion Toolの正本基準で維持し、AI側の記憶に依存しない | Request／ChangeSet相関、冪等Key、Retry、再送検出及び結果照合。 |
| Codexの固有結果・接続失敗をL6の意味結果へ写像できる | 未検証 | 結果が判別できなければ結果不明として扱い、暗黙の成功・失敗にしない | Error、Timeout、Cancel、Rate Limit、認証失敗、情報損失及びRetry-Afterの写像。 |
| Codex接続に必要なSDK、認証又は接続Processが利用可能である | 未検証 | 利用可否はCapabilityの意味契約を変更しない | Provider Adapter、Transport、Protocol、SDK、認証・Secret境界、Process Lifecycle、Version。 |
| Codexが再説明・要約を提供できる | 未検証 | 不提供時は記録済み正本のUI／Tool提示へ縮退できるが、欠落情報を補完しない | Prompt、Grounding、検索・引用、出力品質、利用不能時の提示方式。 |

## 責務境界

- L6-M5-S1はAI非依存のCapability分類を、L6-M5-S3は他AIの意味Capability適合と明示縮退を、L6-M5-S4はL8へのTraceabilityを所有する。本書はCodex以外の適合可否又はL8の実装方式を決めない。
- L6-M1〜M4は情報流、更新・照会、同期・失敗の意味契約を所有する。本書はCodex固有のAPI・順序をその契約へ追加しない。
- L2は状態・遷移・Guard、L3はActor・承認、L4はEntity・正本・履歴・Undo、L5は提示要件を所有する。Codex論理適合だけからこれらを変更しない。
- L7は検証方法、合格条件及びNFR-005の測定を、L8はSDK、Adapter、Model、Prompt、Tool登録、Protocol、認証、Version、Capability検出・交渉、相関・再同期及びUI実装を所有する。
