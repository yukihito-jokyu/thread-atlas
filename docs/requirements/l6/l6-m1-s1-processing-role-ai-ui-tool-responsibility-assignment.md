# L6-M1-S1: 論理処理ロールと AI・UI・Discussion Tool の責務割当

## 目的

L3 が定めるユーザー・AI の Actor 権限とは別に、AI、UI、Discussion Tool が論理処理で担うロールを定める。後続の会話／読取情報流（L6-M1-S2）および更新情報流（L6-M1-S3）は、本書のロール語彙と責務割当を共通前提とする。

本書は情報流の順序、個別 Capability、API、保存 Component を定めない。

## 処理ロール辞書

| 処理ロール | 意味 | 兼任条件 | Actor・権限との分離 |
| --- | --- | --- | --- |
| Initiator | 利用者意図、AI の会話上の判断、又は既存の論理要求を、処理を開始する要求として起点化するロール。 | 同じコンポーネントが Executor を兼任してよい。ただし、起点化だけで正本更新又は承認を導かない。 | 利用者の意図、AI の自動可否、ユーザー確認・承認は L3 が所有する。Initiator は権限主体を表さない。 |
| Executor | 割り当てられた会話生成、入力受領、参照、要求伝達、検証又は更新を実行するロール。 | 一つの処理で複数の Executor がいてよい。各 Executor は自分に割り当てられた論理処理だけを担う。 | 実行できることは L2 の許可経路と L3 の権限に従う。Executor であることだけから更新権限を得ない。 |
| Validator | L2 の規則・Guard と L3 の Actor／承認条件を照合し、要求を適用可能か判定するロール。 | Discussion Tool が更新前に Executor と兼任してよい。照合結果の意味を変更しない。 | Validator は承認主体でも状態遷移の Owner でもない。規則は L2、権限は L3 が所有する。 |
| Canonical Updater | 検証済みの要求を論理正本へ反映するロール。 | Discussion Tool が Executor と兼任してよい。検証前、拒否、又は未確定の要求を反映しない。 | 正本の Entity、Relation、現行値、履歴は L4 が所有する。保存 Component・永続化は L8 が所有し、Canonical Updater と同一視しない。 |
| Presenter | 会話、参照結果又は処理結果を利用者又は AI が確認可能な形で受け渡すロール。 | UI と AI は受取先に応じて兼任してよい。 | 提示、表示フォーカス又は通知だけから正本、状態、決定、現在地を更新しない。提示要件は L5 が所有する。 |

処理ロールは一つのコンポーネントの恒久的な役職ではなく、処理ごとの論理的責任である。AI、UI、Discussion Tool を L3 の Actor に追加しない。

## AI・UI・Discussion Tool の共通責務表

| 処理対象 | Initiator | Executor | Validator | Canonical Updater | Presenter | Actor／権限根拠 | 非導出事項 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 利用者入力 | UI は利用者の入力を要求として受領する。 | UI は入力を AI 又は論理要求経路へ渡す。 | なし。入力の意味上の曖昧さ・確認は後続 Owner が扱う。 | なし。 | UI は入力内容を利用者が確認できるよう提示し得る。 | 意図の意味、確認・承認、入力の確定効果は L3。 | 入力を受けただけで正本更新、承認、通常進行開始を導かない。 |
| AI 会話生成 | AI は会話応答を開始し得る。 | AI は自然言語の質問、再説明、候補又は応答を生成する。 | なし。 | なし。 | AI は応答を UI へ渡し、UI は利用者へ提示する。 | AI の会話上の許容範囲、理解停止等の Guard は L3。 | Discussion Tool を質問生成、提案判断、承認又は自然言語会話の主体にしない。会話生成だけで議論状態の論理正本を更新しない。 |
| 議論状態の参照 | UI 又は AI が参照要求を起点化し得る。 | Discussion Tool は L4 の既存正本を照会し、AI／UI は結果を受け取る。 | Discussion Tool は照会に必要な規則・権限を参照するが、個別の照会条件は後続 Owner に残す。 | なし。 | UI 又は AI は受け取った参照結果を提示し得る。 | 参照可能範囲と Actor 条件は L3、正本は L4。 | 照会、背景再説明、根拠会話閲覧又は表示フォーカス変更から正本更新を導かない。 |
| 変更要求 | 利用者意図又は AI の判断を、UI 又は AI が要求として起点化する。 | UI 又は AI は要求を Discussion Tool へ伝達する。 | Discussion Tool は更新前に L2 Guard と L3 権限を照合する。 | 検証を通過した要求だけを Discussion Tool が L4 正本へ反映する。 | UI と AI は確定した結果又は拒否を受け取る。 | 意図・承認・Actor は L3、状態・遷移・Guard は L2。 | AI／UI が会話、表示又は要求送信だけで L4 正本を暗黙更新しない。 |
| 規則検証 | 更新要求の起点に従う。 | Discussion Tool は検証要求を処理する。 | Discussion Tool は L2 と L3 の定めを照合する。 | なし。 | 検証結果の提示先は UI 又は AI とする。 | 規則の意味は L2、Actor・承認は L3。 | Validator が承認を代行しない。検証成功を正本反映済み又は通知済みとみなさない。 |
| 正本更新 | 検証済みの変更要求に限る。 | Discussion Tool は許可済み更新を実行する。 | 更新直前の L2 Guard・L3 権限照合を Discussion Tool が担う。 | Discussion Tool は論理正本の更新経路を担う。 | UI と AI は更新後に受け取った確定結果を提示し得る。 | L2 の更新可否、L3 の権限、L4 の正本・履歴を参照する。 | 保存方式、DB、SDK 又は通信成功を論理正本更新の意味にしない。これらは L8。 |
| 結果通知 | 確定した更新結果又は照会結果を起点とする。 | Discussion Tool は結果を要求元へ返す。 | なし。 | なし。 | UI と AI はそれぞれの受取結果を提示する。 | 通知の意味と受取先は後続 S2／S3、Actor 権限は L3。 | 未適用、拒否又は結果不明を適用済みとして通知しない。通知だけで追加の更新を行わない。 |

## 共通不変条件

- AI と UI は、会話生成、表示、入力受領、参照又は変更要求の送信だけで L4 の議論状態の論理正本を暗黙に作成・変更しない。
- Discussion Tool は、自然言語の質問生成、提案の三判断、ユーザー承認又は Actor の代理を担わない。更新は L2 の Guard と L3 の権限を照合した後だけに行う。
- AI の会話上の判断は、利用者の承認又は提案の三判断を代替しない。
- UI のローカルな選択、表示フォーカス又は表現切替は、共有正本の現在地、状態、Decision、Proposal 又は履歴の更新ではない。
- 同一コンポーネントのロール兼任は許すが、Validator の照合、Canonical Updater の反映、Presenter の通知を一つの効果として省略又は推測しない。

## 責務境界

- L6-M1-S2 は利用者入力、会話記録、非変更参照、AI 応答、UI 提示の情報流を、L6-M1-S3 は変更要求、検証、正本更新、結果通知の情報流を所有する。本書はそれらの順序、成功・拒否・失敗を定めない。
- L2 は状態・遷移・Guard・構造不変条件、L3 は Actor・承認・統制、L4 は論理正本・Entity・Relation・履歴、L5 は提示要件を所有する。
- 個別 Capability は L6-M2、照会・再説明 Capability は L6-M3、同期・失敗・競合・重複は L6-M4、接続プロファイルは L6-M5 が所有する。
- Process、SDK、Model、Prompt、入力 UI、API、通信、保存 Component、DB、永続化方式は L8 が所有する。
