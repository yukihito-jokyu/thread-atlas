# L6-M4-S3: 競合・古い参照の非上書き／再取得・再判定・再確認契約

## 目的

AI、UI又は再送要求が古い正本・Relation・確認点を前提にするとき、最新のユーザー訂正、Proposal判断、状態、現在地又は構造を暗黙に上書きしない。競合又は古い参照を識別した要求は、最新正本の再取得、L2 Guard及びL3のActor・承認の再判定を経て、同一意図を安全に維持できる場合とユーザー再確認が必要な場合を区別する。

## 共通前提

- 更新及び照会の正常な確認点はL6-M4-S1に、拒否・失敗・部分到達及び結果不明はL6-M4-S2に従う。本書は、これらをL2の業務状態又は新たな永続情報にしない。
- 最新正本はL4が記録済みの正本・Relation・現行結果を指す。会話記録、AIの生成内容、UIローカル状態、表示フォーカス又は過去の応答だけを最新正本の代替にしない。
- 競合又は古い参照の識別は、同じ論理対象、変更意図又は照会範囲について、要求が参照した確認点と再取得した正本の確認点が同一でない、又はその間に意味上関係する更新が確認できる場合に行う。Version、Lock、Queue、比較方式及び検出実装はL8が所有する。
- 再取得、再判定又は再確認の途中で、元要求、会話又は表示を根拠に正本を暗黙更新しない。ChangeSet内部の全適用又は全拒否はL6-M2-S4及びL4に従う。

## 競合・古い参照の非上書きと再確認条件表

| 条件 | 再取得後に確認すること | 要求の扱い | 導かないこと |
| --- | --- | --- | --- |
| AI要求が古い確認点を参照する | 対象、意図、最新の正本・Relation、L2 Guard及びL3のActor・承認を再取得して照合する。 | 一致を確認できるまでAI要求を正本へ適用しない。 | AIの記憶、以前の応答又は会話表現からの正本上書き。 |
| UI操作が古い表示又は選択を参照する | 表示・選択とは別に、対象と最新正本の確認点を再取得する。 | UIローカル状態を更新根拠にせず、再取得した対象に対して再判定する。 | 表示中の値を正本として保存すること、現在地・構造・状態の暗黙変更。 |
| 再送要求が以前の更新結果を参照する | 元要求の同一性、最新正本、既に成立した業務変更の有無及び現在のGuard・権限を確認する。 | 元の成功・失敗・未到達を推測せず、再試行・重複の扱いをL6-M4-S4へ渡す。 | 同一要求の再適用、重複したDecision・Proposal判断・構造更新。 |
| ユーザー訂正又は判断変更が先行している | 再取得した現行内容、旧内容との関係、対象及び要求意図を確認する。 | 古い要求で先行する訂正・判断を上書きしない。要求意図を同一と確認できない場合はユーザー再確認へ渡す。 | 旧内容を現行値として採用すること、訂正・再判断・取消の優先規則の再定義。 |
| 現在地、親子又は復帰先が先行更新されている | L2-M3の構造不変条件、最新の到達経路、現在地及び復帰先を確認する。 | 古い対象経路への更新・再開を適用しない。必要ならL2の許可経路とL3の権限を再判定する。 | 複数現在地、孤立・循環、古い親子又は復帰先の復元。 |
| Guard、Actor又は承認の前提が変化している | 最新のL2 Guard及びL3のActor・承認だけを再判定する。 | 以前の検証済み結果を流用せず、許可されない場合は更新へ進めない。 | Guard解除、権限付与、承認済みへの暗黙昇格。 |
| Proposalの必要性又は現スコープ差異が変化している | Proposalの内容、由来、発見理由、目的との関係、今扱う必要性及び現スコープとの差異を再確認する。 | ユーザーが改めて判断できるようL3-M2及びL1-M2の経路へ渡す。 | 未承認Proposalの通常Topic化、現在スコープ内化、Decision化。 |
| 再取得した最新正本でも要求意図・対象範囲を同一と確認できる | 最新正本に対してL2 Guard及びL3のActor・承認を再判定する。 | 許可されたL6-M2又はL6-M3の通常経路へ戻す。 | 古い確認点のままの適用、再確認不要という一般化。 |
| 対象、意図、範囲又は意味上の前提を同一と確認できない | 不一致の対象・意図・範囲を利用者に確認できるようにする。 | ユーザー再確認の後に、必要なL2/L3経路へ渡す。 | AI又はUIによる意図の推測、要求範囲の縮小・拡大、暗黙の取消。 |

## 再取得後の再判定・再確認の整合条件

- 再取得は、古い要求を最新正本へ自動的に変換する処理ではない。再取得後も対象、意図、範囲、L2 Guard及びL3のActor・承認を別々に確認する。
- 同一意図を安全に維持できるのは、再取得した正本に対し、要求対象・要求内容・適用範囲が変わらず、必要なL2 Guard及びL3のActor・承認を再び満たす場合に限る。その場合でも、実際の更新・照会はL6-M2又はL6-M3のCapabilityに従う。
- 意図又は対象範囲の変化には、ユーザー訂正、Proposalの必要性・スコープ差異、Decision又は完了条件の意味変化、現在地・構造の変化を含み得る。具体的な差分比較又は優先規則を本書で定義しない。
- ユーザー再確認は、確認済みの選択・意図を得るための入口であり、それだけで状態遷移、更新、Decision、Proposal判断、通常Topic化、現在地変更又は正本反映を生じさせない。
- 再取得できない、確認点を比較できない又は競合の有無を確定できない場合は、古い要求を適用せずL6-M4-S2の結果不明及び後続S5の再同期経路へ渡す。

## 責務境界

- L2は状態、遷移、構造、完了及びGuardの意味を、L3はActor、承認、Proposal三判断、理解停止及び訂正を、L4は正本、現行・旧内容、Relation、ChangeSet、履歴及びUndoを所有する。本書は競合時の再取得・再判定・再確認の接続条件だけを定める。
- L6-M1は会話・要求・正本の情報流を、L6-M2は更新Capabilityと原子性を、L6-M3は照会Capabilityと結果分類を所有する。更新又は照会の実行可否を、本書単独で決定しない。
- L6-M4-S2は拒否・失敗・部分到達・結果不明、S4は再試行・重複、S5は途絶・復元後の再同期を所有する。本書は再送の同一性判定、再試行又は再同期を実行しない。
- L5は再確認・競合・差異の提示内容を、L7は数値的な競合率・時間・閾値を、L8はVersion、Lock、Queue、比較、通知、通信、Transaction、補償及びUIの方式を所有する。
