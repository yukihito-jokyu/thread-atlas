# L6-M5-S1: AI非依存の必須・任意・条件付きCapability分類基準

## 目的

L6-M1〜M4で確定したCapabilityを、特定AI製品・SDK・接続方式から独立して、提供者、利用者、必須区分、製品要件上の義務及びMVP含有へ分類する。AI、UI又はDiscussion Toolのいずれか一つを能力そのもの又は論理正本と同一視しない。

本書の分類は意味上のCapabilityに対する要件であり、提供者の検出、交渉、Adapter、Protocol及び実装技術を定めない。

## 分類語彙

| 軸 | 値 | 意味 |
| --- | --- | --- |
| 提供者 | AI / UI / Discussion Tool | Capabilityの論理処理を担える提供者。複数を併記してよいが、Actor・承認主体を表さない。 |
| 利用者 | ユーザー / AI / UI / Discussion Tool | Capabilityの結果を利用又は受け取る主体。UI又はToolを利用者と書いても、ユーザーの承認を代替しない。 |
| 必須区分 | 必須 / 条件付き / 任意 | 必須は該当MVPシナリオで必ず成立する能力、条件付きは明記したTrigger時だけ必要となる能力、任意は必須Capabilityを置換しない追加的なAI支援能力を表す。 |
| 製品要件上の義務 | 常時提供 / Trigger時提供 / 提供してもよい | 必須・条件付きCapabilityの意味契約を製品が守る義務を表す。提供者固有の実装義務ではない。 |
| MVP含有 | 含む / 条件付きで含む / MVP外 | 原典Issue #1のMVP及びFR・AR・NFRに照らす対象範囲。MVP外でも、MVPの必須Capabilityを弱める代替には用いない。 |

「任意」は情報の省略、無応答、又はAI記憶による正本代替を許す意味ではない。AIが任意の支援を提供しない場合でも、必須又は条件付きCapabilityの成功・失敗・結果不明はL6-M4の契約どおりに扱う。

## 欠落時の共通規則

- 必須Capabilityを提供できない構成は、そのCapabilityを必要とするシナリオを開始してはならず、開始済みなら成功・適用済み・同期済みとして扱わない。利用者とAIへ利用不能又は結果不明を区別して伝える。
- 条件付きCapabilityは、表のTriggerが発生した時点で必須になる。代替提供者も存在しない場合は、当該Triggerの更新、完了、再開又は成功通知を禁止し、他の無関係なCapabilityへ暗黙に読み替えない。
- 任意Capabilityの欠落は、記録済み正本に基づくUI又はToolの代替提示を許すが、AIの生成内容、会話上の主張、UIローカル状態又は過去の結果を正本の代替にしてはならない。
- AI、UI及びDiscussion Toolのいずれが提供しても、L2の意味・遷移・Guard、L3のActor・承認、L4の正本・履歴、L5の提示要件を弱めない。提供者の変更だけから権限、承認、状態変更又はDecisionを導かない。
- NFR-005のCapabilityは、製品又は提供者の名称ではなく本表の意味Capabilityを単位に評価する。Capability検出、適合可否の交渉、通知文面及び技術的な縮退実装はL8が所有する。

## 責務境界

- L6-M5-S2はCodex初期接続を本表へ照合する論理プロファイル、S3は他AIの適合と明示縮退、S4はL8へのTraceabilityを所有する。本書はCodex又は他AIの適合結果を確定しない。
- L6-M1〜M4は各Capabilityの意味、情報流、更新・照会契約及び同期・失敗契約を所有する。本書はそれらを提供者別のAPI又は処理順へ再定義しない。
- L7はFR・AR・NFR・MVPの検証方法、合格条件及び指標を所有する。本書はMVP含有の意味上の分類だけを示し、受入試験又は閾値を定めない。
- L8はSDK、Model、Prompt、Adapter、Capability検出・交渉、API、Protocol、認証、UI実装、保存及び通知方式を所有する。
