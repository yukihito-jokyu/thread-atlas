# L6-M4-S4: 再試行・重複要求の冪等な観測結果契約

## 目的

応答喪失、処理失敗又は再送により同じ論理要求が繰り返し届いても、Decision、Proposal判断、状態、構造、現在地、親復帰又はChangeSetの業務変更を最大1回だけ生じさせる。試行の繰返しと正本上の業務変更を区別し、結果不明時の再適用、拒否済み要求の暗黙再実行及び後の別意図の誤った重複扱いを防ぐ。

## 共通前提

- 正常同期点はL6-M4-S1、拒否・失敗・部分到達・結果不明はS2、競合・古い参照の再取得・再判定・再確認はS3に従う。本書はそれらの業務状態、Guard又は権限の意味を変更しない。
- 同一論理要求は、同じ対象、意図、適用範囲及び要求内容として確認できる要求を指す。識別子、比較方式、Idempotency Key、保持期間、再試行回数、Timeout、Protocol及び試行履歴の方式はL8が所有する。
- 同じ内容でも、ユーザーが後に新しい明示意図として要求し、対象・意図・範囲を改めて確認できる場合は、以前の要求との重複として扱わない。L2 Guard、L3のActor・承認及びL6-M2/M3の通常経路を改めて満たす必要がある。
- ChangeSet内部はL6-M2-S4及びL4の全適用又は全拒否に従う。再送を理由に部分適用、業務変更の重複又は既存正本の推測補完を許可しない。

## 再試行・重複要求の観測結果表

| 条件 | 正本上の業務変更 | 再送への観測結果 | 導かないこと |
| --- | --- | --- | --- |
| 同一論理要求が処理中に再送される | 正本反映済みの確認点まで、新たな業務変更を主張しない。 | 処理中の同一要求として扱い、重複更新・重複通知をしない。 | 処理中要求の取消、成功又は失敗の推測、別ChangeSetの追加。 |
| 同一論理要求が反映後・応答喪失後に再送される | 記録済み正本で既に反映済みを確認できる場合、業務変更は最大1回のまま保持する。 | 再送に対し、同じ確定Snapshot又は確認点を参照できる場合だけ、既存の成立結果として扱う。 | 同一更新の再適用、Decision・Proposal判断・親復帰・現在地変更の重複。 |
| 同一論理要求が反映前の失敗後に再送される | 正本反映済みを確認できない限り、以前の試行による業務変更を主張しない。 | S2の失敗・結果不明及びS3の競合確認を参照し、正本確認前に再適用しない。 | 失敗を拒否又は成功へ推測すること、会話・UIからの反映済み判定。 |
| 同一論理要求が論理拒否後に再送される | 拒否された要求は正本を変更しない。 | 同じ明示意図の再送だけでは更新へ進めない。 | Guard解除、権限付与、拒否結果の暗黙取消。 |
| 拒否後に新しい明示意図がある | 新しい要求として、最新正本に対してL2 Guard及びL3のActor・承認を評価する。 | 新しい意図と確認できる場合だけ通常経路へ渡す。 | 同内容であることだけを根拠にした拒否の恒久化又は自動許可。 |
| 既に成立した要求と競合・古い参照がある | 最新正本、対象、意図、範囲及び現在のGuard・権限をS3に従い再取得・再判定する。 | 同一性を確認できるまで既存結果の再通知又は新規適用をしない。 | 古い要求による正本上書き、再送を理由にした競合解消。 |
| 同一性又は反映済みを確認できない | 正本上の業務変更を推定しない。 | 成功・失敗・拒否の確定結果を返したと扱わず、再照会又は再同期の後続経路へ渡す。 | 正本確認前の再適用、過去応答又はUI状態による結果確定。 |

## 冪等な観測結果の整合条件

- 同一論理要求について、正本反映済みの確認点を確認できる業務変更は最大1回である。再送は、その確認点を再び観測・通知できる場合があっても、新しい業務変更を作らない。
- 反映後の応答・表示未到達は、業務変更の重複理由にしない。応答又は表示の再到達はS1/S2の同じ確認点に整合する場合だけ既存結果として扱う。
- 反映前失敗、結果不明又は競合時は、再送を新たな業務変更として実行しない。再照会、競合再判定、再確認及び再同期を経るまで結果を丸めない。
- 論理拒否後の再実行には新しい明示意図を要する。新しい意図の判断主体、承認及び許可はL3、状態・遷移・構造条件はL2、正本・ChangeSet・履歴はL4が所有する。
- 試行の回数、送達、応答又は表示の記録は、業務変更そのものと非同一である。試行履歴のEntity、保持、検索又は可視化を本書で定義しない。

## 責務境界

- L2は状態・遷移・構造・完了・Guard、L3はActor・承認・明示意図、L4は正本・ChangeSet・履歴・Undoを所有する。本書は同一論理要求に対する観測結果と最大1回の業務変更だけを定める。
- L6-M4-S2は失敗・部分到達・結果不明、S3は競合・古い参照、S5は途絶・復元後の再同期を所有する。本書は再送を実行せず、同一性の技術的判定又は競合解消を定めない。
- L5は再送・重複・既存結果の提示内容を、L7は回数・時間・成功率等の測定を、L8はIdempotency Key、履歴、通信、Timeout、Retry、Queue、Transaction、補償及びUI実装を所有する。

## Task固有Review

- 処理中再送、反映後応答喪失、反映前失敗、論理拒否後及び同一性不明を区別した。
- 同一論理要求が正本上の業務変更を最大1回だけ生じさせ、再送が既存結果の観測を重複させても業務変更を重複させないことを確認した。
- 結果不明時の正本確認前再適用を禁止し、拒否後は新しい明示意図を要求し、同内容でも後の別意図を重複扱いしないことを確認した。
- Idempotency Key、試行履歴、保持期間、再試行回数、Timeout、Protocol及び実装方式をL8へ残し、未解決の契約差異又はTBDがないことを確認した。
