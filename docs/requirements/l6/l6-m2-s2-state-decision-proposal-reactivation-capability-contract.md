# L6-M2-S2: 状態・判断結果・提案／再活性化のCapability契約

## 目的

保留・要確認・対象外・Decision・未承認Proposalを混同せず、各許可済みの状態遷移、初回の3判断および論点化を、利用者・AI・UI・Toolの間で実行できる能力として定める。

本書はCapabilityの意味入力、成功時の論理結果および受け手を定める。状態を任意の値へ直接設定する能力、再判断・取消、表示方式、API、実装方式は定めない。

## 共通契約

- Capabilityの呼出しは、対象、利用者の意図またはAIの候補、必要な既存情報をL2の許可遷移とL3の権限へ渡す。ToolはGuardと権限を満たさない更新をL4へ記録しない。
- 成功時は、L2が定める遷移・構造効果を適用し、L4が定める現行正本と一つ以上のChangeSetへ記録する。失敗・拒否時は、対象の状態、現在地、親子、復帰先、Decision、Proposal判断を変更しない。
- AIが実行できる行でも、FR-014に従い追加・変更の内容を確認可能にする。AIは利用者の離脱・再開・再対象化・判断を推測して確定しない。
- UIはCapabilityの入力結果と成功・拒否を表示できるが、UI上の選択・表示フォーカスだけから状態、判断、現在地または構造を変更しない。

## 受け手と責務境界

- Toolは各行の入力をL2 Transition／GuardとL3権限に照会し、許可された場合だけL4の現行情報・Relation・ChangeSetへ渡す。L4のEntity同一性、Cardinality、履歴、Undo、保存・復元単位は変更しない。
- 初回の3判断は本書の対象である。未承認Proposalの再判断、論点化前の取消、ユーザー訂正、業務取消、Undoおよび複数更新の原子性は `L6-M2-S4` へ残す。論点化後の通常Topicは本表の通常Topic能力を含むL2/L3の許可経路に従う。
- 状態語彙・有効組合せ・完了可否・構造効果はL2、Actor・承認・AI統制・理解停止GuardはL3、正本・履歴・ChangeSetはL4が所有する。Capabilityはそれらを直接設定・再定義しない。
- 表示と情報配分はL5、操作の公開形態・API・Schema・実装方式はL8、受入・測定はL7が所有する。本書は具体UI、エンドポイント、入力検出、保存方式を定めない。
