# L6-M1-S3 変更要求・規則検証・正本更新・結果通知の情報流

## 目的

利用者の意図又は AI の会話上の判断を、変更要求、規則検証、論理正本の更新、結果通知へ分けて扱う。未適用又は拒否された要求を、適用済みとして利用者、UI 又は AI に伝えない。

## 前提

- 本書は [L6-M1-S1 の処理役割](l6-m1-s1-processing-role-ai-ui-tool-responsibility-assignment.md)を参照する。Initiator、Executor、Validator、Canonical Updater、Presenter は別の責務である。
- 利用者の意図及び AI の会話上の判断は変更要求の起点情報になり得るが、それ自体は変更、承認、規則検証又は正本更新ではない。
- UI 又は AI は変更要求を Tool へ伝達できる。Tool は会話、承認、判断の主体にならず、要求を受けたことで正本を更新しない。
- Tool による論理正本の更新は、L2 が所有する Guard と L3 が所有する Actor・権限の検証をともに通過した後だけに行う。Guard の意味、権限の判定主体及び更新内容の正本は、それぞれ L2、L3、L4 が所有する。

## 正常・拒否の情報流

| 情報流 | 起点・送信主体 | 受信・実行主体 | 検証と正本への効果 | 結果の全受取先 | 導かないこと |
| --- | --- | --- | --- | --- | --- |
| 変更要求の起点化 | 利用者の意図又は AI の会話上の判断 | UI 又は AI が変更要求として Tool に伝達する | 要求を表すだけであり、L4 の正本は更新しない | 要求を起点にした利用者、UI、AI | 意図又は AI 判断だけから、Actor、承認、提案の三判断、状態変更を導かない |
| 変更要求の受領 | UI 又は AI | Tool | Tool は要求を受領し、L2 Guard と L3 の権限を検証する対象として扱う。受領だけでは L4 を更新しない | 要求元、UI、AI | Tool が会話を開始すること、要求を承認すること、表示情報を正本へ反映すること |
| 正常な更新 | Tool | Tool が L4 の論理正本更新へ接続する | L2 Guard と L3 の権限がともに検証済みで、更新が正本へ反映された場合だけ、適用済みの結果を確定する | 要求元、UI、AI | UI の表示フォーカス、会話記録、要求送信又は検証済みであることだけから正本更新を導くこと |
| 規則拒否 | Tool | Tool が拒否結果を返す | Guard 又は権限の検証を通過しない要求は L4 の正本を更新しない。拒否結果は未適用として扱う | 要求元、UI、AI | 拒否を適用済み、承認済み、状態変更済み又は確定済みとして通知すること |
| 結果の受領と提示 | Tool | 要求元、UI、AI。UI は Presenter として結果を提示できる | 適用済みの結果は正本への反映後だけを通知し、拒否又は未適用の結果はそのまま区別して通知する | 利用者、UI、AI | 結果の提示、UI のローカルな選択・フォーカス又は AI の会話上の応答から、追加の正本更新を導くこと |

## 不変条件

- 要求、検証中、拒否、未適用及び適用済みを同一の結果として扱わない。適用の成否が確認できない結果も、適用済みとして通知しない。
- UI、AI 又は Tool は、会話、読み取り結果、表示、要求の受領又は検証情報だけを根拠に、L4 の正本を暗黙に更新しない。
- Tool は L2 の Guard 又は L3 の Actor・権限を変更、解除又は代理承認しない。L2 と L3 の検証を通過しない要求を L4 へ渡さない。
- UI のローカルな選択・フォーカスは表示上の状態であり、論理正本の更新、現在地変更、状態遷移又は決定の確定を意味しない。
- 会話及び読み取り情報の流れは L6-M1-S2 が所有する。そこからの記録・参照は、変更要求又は正本更新を自動的に発生させない。

## 責務境界

- 個別の更新操作とその能力は L6-M2、検索・集約などの参照能力は L6-M3 が所有する。
- 部分失敗、競合、再試行、遅延、順序及び要求の最終的な実行失敗の扱いは L6-M4 が所有する。本書は正常な更新と規則拒否の情報流だけを定める。
- API、Transaction、通知の具体的な UI、非同期処理及び実装方式は L8 が所有する。
- L2 は状態・遷移・Guard、L3 は Actor・承認・権限、L4 は Entity・Relation・論理正本・履歴、L5 は提示要件を所有する。本書はそれらを更新する条件と結果の受け渡しだけを扱う。
