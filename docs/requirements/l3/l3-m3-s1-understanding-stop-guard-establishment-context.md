# L3-M3-S1: 理解停止Guardの成立条件と対象文脈

## 目的

ユーザーが現在の論点を理解できないため進行を止めるという明示意図を、通知時点の一つの現在論点とその文脈だけへ結び付ける成立規則を定める。

| Rule ID | 規則 |
| --- | --- |
| `L3-M3-S1-R-01` | 文章入力を要しないユーザーの明示通知による成立 |
| `L3-M3-S1-R-02` | 通知時点の一意な現在論点・文脈への対象化 |
| `L3-M3-S1-R-03` | 非成立条件と後続Ownerへの委譲 |

## 成立条件

理解停止Guardは、次をすべて満たすときだけ成立する。

- 文章入力を要しないユーザー通知により、現在の論点を理解できないため議論の進行を止める意図を明示する。入力手段と検出方式はL8が所有する。
- 通知時点の現在論点を一意に確認でき、ルートからの経路、背景、決めたいこと、完了条件、既知の残り論点および復帰先を同じ文脈として確認できる。
- 対象はその現在論点と通知時点の文脈だけである。別論点、次論点、親子関係、現在地または既存の決定・完了条件を変更しない。
- 正常完了、AI認識修正、ユーザー都合の中断・再訪を処理中ではない。これらを処理中の場合はGuardを成立させず、それぞれのOwnerへ委譲する。

この成立は、理解停止を永続状態へ追加せず、一時Guardとして扱う。正式な状態語彙・遷移・現在地変更はL2が所有する。

## 非成立条件

次のいずれも、理解停止Guardの成立を導かない。

- AIによる理解不足の推定、沈黙、応答の遅延または過去の会話からの類推。
- 現在の論点を特定しない通常の背景再説明要求。再説明要求だけではGuardの成立または解除を確定しない。
- 同じ通知の反復、または理解停止の意図を明示しない不満・質問。
- 現在論点または対象文脈を一意に確認できない入力。曖昧な入力の確認はL3-M4-S1へ委譲する。

## 責務境界とTask固有Review

- Guardの維持、停止中のAI許可・禁止動作はL3-M3-S2、ユーザー明示による解除と通常進行復帰はL3-M3-S3が所有する。
- 背景再説明と利用者から見える反復はL1-M3-S2、入力検出方式・UI・説明生成はL8が所有する。
- 会話・Guardの保存モデルと履歴はL4、表示はL5、論理操作/APIはL6、受入・測定はL7が所有する。
- [x] ユーザーの明示意図と、通知時点の一意な現在論点・文脈を成立条件にした。
- [x] 文章入力を要しない通知を成立入口とし、競合する処理中には成立させない。
- [x] AI推定、直接再説明要求、反復通知からの成立を禁止した。
- [x] 理解停止を永続状態にせず、L2の状態・遷移を再定義していない。
