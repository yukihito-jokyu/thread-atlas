# L3-M1-S1: Actor語彙・権限区分・主表記載規則

## 目的

L2で許可された操作と抽象Guardへ、ユーザーとAIの責任を矛盾なく割り当てるためのActor語彙、4権限区分、Guard区分およびL3-M1主表の記載契約を定める。

本書は個別操作のActor割当を行わない。通常系はL3-M1-S2、離脱・再開・再活性化系はL3-M1-S3、例外系はL3-M1-S4が主表の行を所有する。

## Actor語彙と責任

| Actor | 本書での責任 | Actorにしないもの |
| --- | --- | --- |
| ユーザー | 意図を示し、確認・承認・取消・訂正を行う意味上の主体。ユーザーのみまたはユーザー確認必須の行で必要な意思決定を担う。 | UI、画面、入力部品、保存先、API。これらはユーザーの意思表示手段であってActorではない。 |
| AI | L2とL3で許可された範囲だけで、候補提示、確認可能な内容の更新または処理を担う意味上の主体。未割当の操作やGuardを推測で実行しない。 | Tool、Adapter、Model、Prompt、Provider、実行プロセス。これらはAIの実装・連携方式でありActorではない。 |

Actorは上表の二者だけとする。複数のAI、UI、Tool、Adapterの具体的な責任分担、認証、実装上の実行主体はL6/L8が扱う。

## 4権限区分

| 区分 | 意味 | AIに許される範囲 | ユーザーとの関係 | 禁止する読み替え |
| --- | --- | --- | --- | --- |
| AI自動可 | L2の許可条件と当該行のGuardを満たす限り、AIが事前の明示確認なしに実行できる。 | 行が定める更新または処理を実行できる。 | 事前の明示確認を当該行の前提にしない。ただし、FR-014が求める更新後の追加・変更・完了の可視化と確認可能性は免除しない。 | L2の禁止行・不成立Guard・未割当操作を自動実行できること。 |
| 提案のみ | AIは候補、根拠または選択肢を提示できるが、当該操作の確定効果を実行できない。 | 提案の提示まで。状態・構造・決定・現在地の確定更新はしない。 | ユーザーの意思決定後にどの操作が可能かは、対応する別行と詳細Ownerに従う。 | 提案の登録、表示または再説明を、承認済みの遷移・論点化・決定とみなすこと。 |
| ユーザー確認必須 | AIが候補作成または処理を担い得るが、確定効果にはユーザーの明示確認を要する。 | 明示確認後に限り、行が許す処理を担い得る。確認前は確定効果を生じさせない。 | 確認の意思決定はユーザーが担う。確認の検出方式・UIは定めない。 | AIの推測、無応答、過去の確認を現在の確認として扱うこと。 |
| ユーザーのみ | 当該操作の実行・確定効果はユーザーだけが担う。 | 候補提示も含めたAIの関与可否は個別行の詳細Ownerに委譲し、少なくとも確定実行はしない。 | ユーザー自身の明示操作または意思表示を要する。 | AIの代理実行、AI提案からの自動確定、ユーザー確認必須との同一視。 |

区分はL2の許可範囲を広げない。すべての行でL2の起点、遷移先、禁止遷移、状態組合せ、完了条件および階層不変条件を先に満たす必要がある。

## Guard区分

| Guard区分 | 主表での扱い | 例 | Actor割当 |
| --- | --- | --- | --- |
| 操作権限Guard | 操作を実行できる権限区分と実行Actor・承認Actorを記載する。 | AI自動可、提案のみ、ユーザー確認必須、ユーザーのみ。 | 必須。 |
| 意思決定・承認Guard | ユーザーの確認または承認を要することと、詳細Ownerを記載する。 | 提案の3判断、論点化、訂正の受入。 | 必須。詳細な成立条件は兄弟Ownerが定める。 |
| 条件成立Guard | L2の状態・完了・構造・到達可能性など、操作の可否を制約する条件を根拠IDとして参照する。 | 有効組合せ、正常完了可能、親復帰、単一現在地。 | Actor制御対象外。条件そのものに権限区分を付与しない。 |
| 禁止Guard | 操作を許可しないことを示すL2の禁止条件を参照する。 | 不正組合せ、未承認提案の論点化、理解停止中の進行。 | Actor制御対象外。禁止行へ実行Actor・承認Actorを割り当てない。 |

条件成立Guardと禁止Guardは、AIまたはユーザーが実行する操作ではない。主表では`Actor制御対象外`とし、これらを満たすための操作をAIへ暗黙に割り当てない。

## 主表の列・ID・記載規則

L3-M1-S2〜S4の主表は、全L2 Transition／GuardおよびFR-008の構造更新を重複なく一行ずつ記載し、少なくとも次の列を持つ。

| 列 | 記載規則 |
| --- | --- |
| 権限行ID | `L3-M1-S{2|3|4}-A-{連番}` とする。S1は共通契約のみを所有し、操作行IDを発行しない。 |
| 対象操作／Guard | L2のTransition IDまたはGuard IDを正確に参照する。FR-008の論点追加・更新、親子関係、現在地設定は、原典IDと対応するL2根拠IDを併記する。L2の内容を複製・変更しない。 |
| 区分 | 操作権限Guardでは4権限区分の一つ、条件成立・禁止Guardでは`Actor制御対象外`を記載する。 |
| 実行Actor | 操作権限GuardだけにユーザーまたはAIを記載する。Actor制御対象外では`なし`とする。 |
| 承認Actor | 承認が必要な行だけにユーザーを記載し、それ以外は`不要`または`なし`を明記する。 |
| 取消／訂正Owner | 取消・訂正・再判断を扱う詳細Ownerを記載する。未定義の取消権を新設しない。 |
| 詳細Owner | S2〜S4、L3-M2〜M4または他層の唯一の詳細Ownerを記載する。 |
| Guard区分・根拠ID | 前節の区分と、L2・原典・兄弟成果物の根拠IDを記載する。 |
| 責務境界 | L2の遷移可否、L4の履歴、L5の表示、L6の論理操作、L7の受入、L8の実装を再定義しないことを記載する。 |

未割当の操作はAI自動更新を禁止する。主表の対象操作に該当しないAIの候補提示は、それ自体を確定更新にせず、提案のみとして詳細Ownerへ引き渡す。行の区分、実行Actor、承認Actor、根拠IDまたは詳細Ownerが欠ける場合、その行は確定割当として扱わない。

## 責務境界

- L2は操作・遷移・禁止・状態組合せ・完了・階層不変条件を所有する。本書および主表はそれらを変更しない。
- L3-M1-S2は通常進行・構造更新・完了条件・決定・正常完了、S3は保留・中断・再開・対象外・決定済み再開、S4は提案・理解停止・要確認・訂正・抽象的なUndo実行の個別割当と詳細Owner接続を所有する。Undoの対象・粒度・履歴関係はL4-M4が所有する。
- L3-M2は提案登録・三判断・論点化承認、L3-M3は理解停止Guard、L3-M4は曖昧発言と訂正優先を所有する。
- Entity・履歴・Undo・保存はL4/L8、表示はL5、論理操作・APIはL6、受入基準・測定はL7が所有する。
