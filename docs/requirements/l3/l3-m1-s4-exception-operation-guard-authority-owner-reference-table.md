# L3-M1-S4: 例外系操作・Guardの基準権限と詳細Owner対応表

## 目的

提案、理解停止、要確認、明示訂正および抽象的なUndo実行について、L3-M1-S1の4権限区分を基準として割り当て、固有の成立・解除・優先規則を一意の兄弟Ownerへ接続する。

## 共通前提

- 本表は例外系のActor区分と詳細Ownerへの接続だけを定める。L2の許可遷移・状態組合せ・構造条件を変更せず、兄弟Ownerが条件を狭めてもL2の許可範囲を広げない。
- 条件成立Guardと禁止Guardは`Actor制御対象外`である。Actorに操作を暗黙に割り当てず、未割当のAI自動確定を禁止する。
- ユーザー直接実行はその明示操作自体を確認とする。AI実行にユーザー確認が必要な行は、確認前に確定効果を生じさせない。

## 責務境界とReview

- S2・S3の通常・離脱／再活性化遷移行を複製しない。新規提案の登録・判断・再判断はL3-M2、理解停止の成立・維持・解除はL3-M3、曖昧発言・訂正優先はL3-M4が固有規則を所有する。
- Entity・履歴・Undo・保存はL4/L8、表示はL5、論理操作・APIはL6、受入・測定はL7が所有する。

- [x] 兄弟Ownerが条件を狭めてもL2の許可範囲を広げない規則と、禁止GuardのActor制御対象外を定めた。
- [x] 実行Actor、承認Actor、取消／訂正Owner、詳細Owner、根拠IDを全行に記載した。
