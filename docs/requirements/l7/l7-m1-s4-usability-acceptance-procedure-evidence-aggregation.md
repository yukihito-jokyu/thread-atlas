# L7-M1-S4 ユーザビリティ受入の実施手順・証跡・合否集約規則

## 目的と入力

L7-M1-S1の代表利用者・評価タスク・規模・Oracle、L7-M1-S2の操作負荷閾値、L7-M1-S3の理解成果閾値を、再現可能なユーザビリティ受入へ統合する。本書は各閾値を変更又は複製しない。

## 実施単位と標本

- 一つの有効実施は、S1が定めた一つの代表課題・規模・開始点・終了点を、一人の代表個人利用者が完了又は不合格となるまで実施する単位とする。
- 各代表課題・規模には、異なる代表個人利用者による有効実施を3件以上そろえる。参加者の詳細属性は記録しない。各人は同じ課題を一回だけ実施する。
- 同一人の再試験、無効実施又は中断実施は標本数に数えない。小・標準・大、及び別の代表課題を相互に代替又は平均化しない。
- 画面固有の操作手順、参加者募集方法、データ生成、回答入力・記録ツールはL8が所有する。

## 事前説明と準備

実施前に、次の事項だけを同一内容で伝える。

1. 評価対象は画面で確認できる情報と、開始点から終了点までの課題達成である。
2. 正答、構造、状態又は操作方法の説明は提供しない。評価中にAI又は評価者へ追加の説明を求めない。
3. 不明な場合は未回答として扱える。実施を中断したい場合は申し出られる。
4. 意図的な要件変更は可能だが、Oracleに対する誤認訂正とは別に記録する。

課題ごとに、S1のOracle、規模、開始点・終了点、及びS2/S3で適用する評価項目を事前に固定する。評価者はOracleを採点のためだけに保持し、利用者へ示さない。評価用Session・初期データは各実施で独立させ、前の実施の変更を次の実施へ持ち込まない。

## 実施順と観測

最初に採点しない導入操作を一回だけ行い、画面の基本的な操作可能性を確認する。導入操作の結果は標本、負荷又は理解成果に含めない。

採点する代表課題は、各利用者について次の順に実施する。各課題の規模はS1に定めるものを用いる。

1. 新規壁打ち開始
2. 一問一答の通常進行
3. AI認識の訂正
4. 正常完了と親復帰
5. 新規提案の三判断
6. 理解停止と背景再説明
7. 中断と同一Session内再訪
8. Session再開
9. 全体／フォーカスの確認と切替

各課題について、開始時点、終了又は中断時点、タスク達成の有無、S2の必須意味操作・各余分負担・探索理解時間、S3の適用設問と重要情報ごとの回答区分を観測する。S3の回答は、表示可能なUIの情報だけに基づくものとしてOracleへ照合する。観測者は利用者へ誘導、補完又は訂正をしない。

## 実施状態、除外及び中断

| 状態 | 定義 | 標本・合否への扱い |
| --- | --- | --- |
| 未実施 | 課題を開始していない。 | 標本に数えない。合格にも不合格にも集約しない。 |
| 有効・合格 | 課題を開始から終了まで実施し、S2及びS3の全適用項目を満たす。 | 有効標本として数え、当該課題・規模の合格1件とする。 |
| 有効・不合格 | 課題を開始から終了まで実施したが、未達成、S2閾値超過又はS3の不正答・未回答・概念混同が一つでもある。 | 有効標本として数え、当該課題・規模の不合格1件とする。 |
| 無効 | 評価開始前からのデータ破損、評価環境の外部障害又は評価者手順逸脱により、S1〜S3を測定できない。利用者の誤答、探索、再入力、操作負荷又は中断希望を無効理由にしてはならない。 | 標本に数えず、原因を証跡に残す。代替実施を一回新たに行う。 |
| 中断 | 利用者が中断を申し出た、又は安全上継続できない。 | 標本に数えず、中断時点と理由を証跡に残す。合否へ置き換えない。 |
| ブロック | 必要な評価環境又は入力が利用できず開始できない。 | 標本に数えず、未実施と区別して原因を証跡に残す。 |

無効・中断・ブロックを、合格又は不合格へ読み替えない。利用者がOracleを確認できなかった結果は、外部障害に該当しない限り有効・不合格として扱う。

## 非相殺の合否集約

一つの有効実施は、次の全条件を同時に満たすときだけ合格とする。

1. S1の終了点に到達し、タスク達成Oracleと矛盾しない。
2. S2の規模別閾値について、再入力、AI誤認訂正、後戻り・探索、手動構造維持及び探索・理解時間の全項目が上限以内である。
3. S3の当該課題に適用されるQ1〜Q8及び重要情報項目がすべて正答であり、誤答・未回答・概念混同がない。

同じ実施内で、操作負荷が低いこと、別設問の正答、別課題・別規模・別利用者の結果、又は表示上の好みを用いて、未達成、閾値超過、不正答、未回答又は概念混同を相殺してはならない。

代表課題・規模ごとの受入状態は、3件以上の有効実施がそろった後に次で確定する。

| 集約状態 | 条件 |
| --- | --- |
| 未実施 | 有効実施が0件である。 |
| 実施中 | 有効実施が1〜2件であり、まだ合否を確定できない。 |
| 不合格 | 有効実施に不合格が1件でもある。 |
| 合格 | 有効実施が3件以上あり、全件が合格である。 |

集約は課題・規模ごとに独立して行う。複数課題の総合値、平均値又は達成率で重要項目の不合格を覆い隠さない。L7-M1全体は、対象となる全ての代表課題・規模が合格のときだけ合格とする。

## 再試験

- 無効又はブロックの解消後は、未測定分として新しい実施を行う。元の無効・ブロック記録を削除又は置換しない。
- 有効・不合格を受けて、要件又は実装を変更した場合は、新しい評価サイクルとして該当課題・規模の有効実施を3件以上あらためて行う。過去サイクルの合格を再利用しない。
- 中断実施は、同一人に継続を強制しない。別の代表個人利用者による新しい実施を追加できる。
- 再試験は不合格結果を消すための上書きではない。サイクル、実施、状態及び変更有無を区別して証跡に残す。

## 証跡とM6への受渡し

各実施には、少なくとも次を対応付ける。

| 証跡項目 | 内容 |
| --- | --- |
| 評価サイクル・実施識別子 | 同一変更後の一連の評価と、その中の一実施を区別する参照。 |
| 入力基準 | S1の課題ID、規模、開始・終了点、Oracleの版、S2/S3の基準版。 |
| 実施状態 | 未実施、有効・合格、有効・不合格、無効、中断又はブロックと、その理由。 |
| S2観測結果 | タスク達成、必須意味操作、各余分負担、探索・理解時間、適用した規模別閾値との照合。 |
| S3観測結果 | 適用したQ1〜Q8・重要情報項目、各回答区分、Oracle照合結果。 |
| 非相殺判定 | 不合格となった個別条件、又は全適用条件を満たした根拠。 |
| 再試験関係 | 元実施、変更有無、新規実施との関係。 |
| 証跡参照 | 観測記録、Oracle照合、集約結果をたどるための参照。具体的な保存形式・索引方式は定めない。 |

L7-M6へは、課題・規模ごとの集約状態、各実施状態、適用基準版、非相殺判定及び証跡参照を渡す。M6は全要件とのTraceability及び証跡索引を所有し、本書は索引形式を定めない。

## 責務境界

- S1は代表利用者、課題、規模、開始・終了点及びOracleを所有する。S2は操作負荷の意味・計数・閾値、S3は理解成果の設問・回答区分・閾値を所有する。本書は実施・状態・集約に限る。
- 状態・遷移・完了可否はL2、Actor・承認・GuardはL3、論理正本・履歴はL4、提示すべき意味はL5が所有する。評価結果からそれらを変更しない。
- 応答時間・同期性能はL7-M2、具体UI、評価ツール、計測・ログ実装、データ生成及び試験実行はL8以降が所有する。

## Task固有Review

- 事前説明、固定入力、導入操作、全代表課題の実施順及び観測項目を定義した。
- 標本数、未実施・有効合格・有効不合格・無効・中断・ブロックを分離し、利用者の失敗を除外しない規則を定めた。
- S2/S3の閾値を複製せず、全適用項目の非相殺合否、課題・規模ごとの集約及び再試験規則を定めた。
- M6へ渡す証跡項目を定義し、具体的なUI、ツール、ログ又は索引方式を残した。
