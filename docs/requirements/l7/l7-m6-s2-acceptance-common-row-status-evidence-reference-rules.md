# L7-M6-S2 受入仕様の共通行形式・状態・証跡参照規則

## 目的

L7-M6-S3 の全要件受入・Traceability 表、S4 の監査台帳及び S5 の証跡索引が同じ意味で参照できる、受入仕様の共通行、Acceptance ID、状態及び証跡参照の規則を定める。本書は L7-M1〜M5 の分野別基準値、測定手順、Case 又は実施結果を変更・複製しない。

## 共通識別子

- 受入仕様は `ACC-0001` 形式の一意な `Acceptance ID` を用いる。番号は L7 全体で再利用せず、欠番を詰めない。
- Requirement ID と Dataset ID は統合担当の共通 Registry を参照し、`Acceptance ID` へ置換又は再採番しない。Requirement の意味・Dataset の内容、物理形式又は生成方式は各 Owner が所有する。
- Scenario ID、Q ID、派生 Requirement／Capability ID、分野固有の Measurement／Fixture／Case／Run／Evidence ID は、指定単一 Owner の既存識別子のまま参照する。具体的な採番・保存・相関方式は後続の L8-M8 等が確定し、本書は先取りしない。
- 一つの `Acceptance ID` は一つ以上の Requirement 等を参照でき、一つの Requirement 等は複数の `Acceptance ID` に対応してよい。対応の Cardinality と全件の割当は S3 が所有する。

## 共通受入行形式

S3 の中央表に置く各受入行は、少なくとも次の列を持つ。MVP 外又は正当非該当の行も、根拠と状態を保持して削除しない。

| 列 | 記録する内容 | 本書から導かないこと |
| --- | --- | --- |
| Acceptance ID | 本書の予約形式による一意 ID。 | 実装上の Case、Run 又は Evidence ID。 |
| 原典・派生根拠 | FR／AR／NFR／MVP、Scenario、Q、派生 Requirement／Capability と版又は参照。 | 近接した要件からの根拠補完。 |
| Owner | 要件、受入仕様、実行及び詳細設計の各 Owner。 | 単一 Owner の重複又は移管。 |
| MVP・適用範囲 | MVP 内／MVP 外、対象利用者・Session・Profile・規模・Trigger 等の適用境界。 | MVP 外を MVP 受入へ混入すること。 |
| 前提・固定入力 | 事前状態、正本、Actor／Guard、環境、データ、開始・終了点又は適用基準版。 | 未記録の前提、初期値又は正本の推測。 |
| 受入方法 | Scenario、契約照合、Inspection、測定又は分野 Owner が定める客観的方法への参照。 | 実装方式、試験 Tool 又は手順の新設。 |
| 期待結果・禁止 | 観測可能な成功、拒否、停止、非変更又は禁止事項。 | 実装後の実行結果又は正本変更。 |
| 客観的合否 | 合格・不合格を決める Oracle、閾値、非相殺又は例外規則への参照。 | M1〜M5 の数値・分類・手順の複製。 |
| 仕様定義状態 | 下表の定義状態。 | 試験実行の合否。 |
| 試験実行状態 | 下表の実行状態と、分野 Owner が持つ詳細状態への参照。 | 要件定義の完成又は Gate 通過。 |
| 証跡計画・参照 | 証跡種別、生成段階、ライフサイクル状態、既存参照及び欠測理由。 | 保存先、索引、収集方式又は改変検出方式。 |
| 参照基準 | M1〜M5 又は L1〜L6 の基準 ID・版・適用条件。 | 参照先の基準の再定義。 |
| L8 受渡し領域 | UI、Tool API、AI Adapter、永続化、実行時整合又は計測試験などの設計領域。 | L8 子 ID、SDK、Schema、Harness 又は実装方式の指定。 |

## 状態の分離

### 仕様定義状態

| 状態 | 意味 |
| --- | --- |
| 未定義 | 共通行又は客観的合否・証跡計画が未確定である。 |
| 定義済み | 共通行の必要列、客観的合否及び証跡計画を参照で確認できる。実測済みを意味しない。 |
| 正当非該当 | 適用 Trigger 又は対象が成立しないことを根拠付きで確認した。欠落・不合格の代替ではない。 |
| MVP外 | 保持対象だが MVP 受入・総合合否に含めない。MVP 境界の根拠を持つ。 |
| 要解消 | 欠落、重複、矛盾又は Owner 不明があり、受入仕様として確定できない。監査の詳細と解消は S4 が所有する。 |

`定義済み`だけが要件ベースライン Gate の仕様完成候補になり得る。`未定義`、`要解消`、又は根拠のない`正当非該当`を合格へ読み替えない。

### 試験実行状態

| 状態 | 意味 | 合格への扱い |
| --- | --- | --- |
| 未実施 | 対応する受入実施を開始していない。 | 合格ではない。 |
| 実施中 | 開始済みだが、必要な観測又は証跡がそろっていない。 | 合格ではない。 |
| 未検証 | 前提、観測、Oracle 又は証跡を確認できず判定不能である。 | 合格・不合格へ推測変換しない。 |
| 合格 | 参照先の全適用 Oracle と必要証跡を確認できた。 | 当該受入行だけの実行結果である。 |
| 不合格 | 必要な観測と Oracle を照合でき、要求を満たさない。 | 他行又は別分野の合格で相殺しない。 |
| 無効 | 実施は試みたが、外部障害・記録破損等で妥当な合否を置けない。 | 合格に丸めず、詳細の除外可否へ参照する。 |
| 中断 | 利用者又は安全上の理由で実施を完了しなかった。 | 未実施・無効・不合格と混同しない。 |
| ブロック | 必要な入力、環境又は確認経路に到達できない。 | 合格ではない。 |
| 非該当 | 条件付きの Trigger が不成立で、当該受入を要求しない。 | 合格件数又は不合格件数へ算入しない。 |

分野固有表がより細かい実施状態を持つ場合、その状態・理由・集約規則を保持したまま上表の最も近い意味を併記する。M6 は分野固有の標本数、閾値、無効・中断・再試験又は非相殺の規則を上書きしない。実行状態は仕様定義状態と独立し、実測前の`未実施`又は`未検証`は`不合格`と区別するが、合格扱いもしない。

MVP 内の必須受入行に`未実施`、`実施中`、`未検証`、`無効`、`中断`又は`ブロック`が一つでも残る場合、総合合格を導かない。総合の集約対象、例外及び不合格との扱いは S3 と各分野 Owner が定め、本書は総合結果を算出しない。

## 証跡ライフサイクルと参照

各受入行は、少なくとも一つの証跡計画を持つ。証跡は論理的な参照であり、実体の保存・検索・収集・改変検出は L8 が所有する。

| 証跡状態 | 意味 | 許されない読み替え |
| --- | --- | --- |
| 未計画 | 必要な証跡種別又は生成段階を定めていない。 | 定義済み又は実施済み。 |
| 計画済み | 証跡種別、生成段階、対応する受入行と参照基準を定めた。 | 証跡が生成済みであること。 |
| 生成待ち | 実行又は後続設計を待ち、まだ記録済み参照がない。 | 欠測の不存在理由。 |
| 生成済み | 記録済み証跡への参照がある。 | Oracle との照合又は合格。 |
| 参照確認済み | 必要な証跡参照と受入行・基準との対応を確認できる。 | 実行結果の合格。 |
| 利用不能 | 必要な証跡参照に到達できない又は内容を確認できない。 | 未実施、無効又は不合格のどれかへの自動変換。 |

- 証跡参照は、証跡種別、生成段階、対象の `Acceptance ID`、参照基準、状態及び参照不能ならその記録済み理由を持つ。M6 は Evidence ID、保存先又は収集方式を生成しない。
- 証跡の`生成済み`又は`参照確認済み`だけから合格を導かない。実行状態は客観的合否と該当証跡を合わせて決める。
- 再実施、再測定又は再照会は新しい証跡参照を追加し、過去の実行状態・証跡参照・不合格理由を削除又は上書きしない。どの記録を現行の実行結果として採用するかは分野 Owner と S5 の索引規則へ委ねる。

## M1〜M5 の参照規則

| 分野 | M6 行が参照するもの | M6 が複製・再定義しないもの |
| --- | --- | --- |
| L7-M1 ユーザビリティ | 代表課題・規模・Oracle、操作負荷・可読性の基準 ID、実施・集約証跡。 | 対象者、操作手順、閾値、標本数、回答区分、集約。 |
| L7-M2 応答性 | 観測点・区間、Profile、結果別指標・閾値、実施状態・証跡。 | Clock、計測方式、percentile、標本、Timeout、欠測・除外。 |
| L7-M3 可逆性 | Undo Case／展開 Case、原子性・履歴 Oracle、実施・集約証跡。 | ChangeSet 分類、依存閉包、Undo 可否、操作手順、非相殺。 |
| L7-M4 永続性 | 復元対象・Profile、再開・閉包・安全停止 Oracle、実施・集約証跡。 | 7対象の意味、復元手順、停止判断、Session 分離、保持・環境。 |
| L7-M5 AI非依存 | Capability × Profile、意味適合・不足禁止 Oracle、実施・集約証跡。 | Provider、Capability 意味、縮退可否、前提、Profile、集約。 |

一つの受入行が複数分野を参照しても、各基準は参照先 Owner の版・適用条件とともに記録する。分野間の結果、標本、閾値又は実施状態を平均化・代替・相殺しない。

## 責務境界

- S1 は要件全集合、MVP 境界及び Owner 台帳、S3 は全要件の中央 Traceability 表、S4 は監査台帳と解消結果、S5 は証跡索引と L8 受渡しを所有する。本書は共通行、語彙及び参照規則だけを所有する。
- L1〜L6 は要件・シナリオ・状態・Actor・正本・提示・Capability の意味を、L7-M1〜M5 は分野別基準と実施規則を所有する。本書の状態・証跡語彙からそれらを変更しない。
- L8-M8 等の指定単一 Owner は Case／Run／Evidence ID、Fixture、Harness、Tool、Clock、Trace、保存、検索、改変識別、試験実行及び集約の実装方式を所有する。本書は具体方式、L8 子 ID 又は実測の完了を定めない。
