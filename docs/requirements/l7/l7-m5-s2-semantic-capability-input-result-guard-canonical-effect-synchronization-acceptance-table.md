# L7-M5-S2: 更新・照会・通知Capabilityの意味適合表

## 目的

L7-M5-S1の各プロファイルが、L6で既定の更新・照会・通知の意味契約を保つための受入条件を定める。文面、JSON、SDK、呼出順又は表示実装の一致は要求しない。

## 意味適合表

| 対象Capability | 意味入力 | 成立結果 | Guard・正本効果 | 同期・最大1変更 | 不成立・非導出 |

| 正規更新（L6-M1-S3、L6-M2-S1〜S4、L6-M4-S1） | 明示要求と記録済み正本、L2/L3の許可結果 | Toolが確定した成功・拒否・失敗・結果不明のいずれか | 成功時だけL4正本を許可経路に従って変更する | 同一論理要求は業務変更を最大1回。確定Snapshot後だけ会話・UIを同期する | AI発話、UI送信又は表示だけから更新・承認・同期完了を導かない。 |

## プロファイル横断規則

- `P-C`、`P-A`、`P-N`のいずれでも上表を適用する。`P-N`での不足禁止と明示結果はL7-M5-S3、実施・証跡・非相殺合否はL7-M5-S4が所有する。
- 条件付きCapabilityは、対応するTriggerが成立した場合だけ上表の意味適合を満たす。Triggerが不成立のときは非該当であり、不足、失敗又は成功へ読み替えず、当該Capabilityによる更新・成功・同期も導かない。
- Capabilityの適合は意味入力、意味結果、Guard、正本効果、同期及び最大1変更をすべて満たす場合だけ成立する。一部だけ満たしても部分成功にしない。
- L2の状態・遷移、L3のActor・承認、L4の正本・履歴・Undo、L5の提示要件は既存Ownerに従う。本書はProviderの違いを理由に意味契約を緩和しない。
- L8はSDK、Adapter、Prompt、Tool呼出し、Protocol、相関、表示・通知及び計測実装を所有する。本書は実装方式を選定しない。
