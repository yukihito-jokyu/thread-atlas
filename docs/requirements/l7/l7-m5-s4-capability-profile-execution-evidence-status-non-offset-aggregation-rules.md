# L7-M5-S4: AI適合性受入の実施・証跡・合否集約規則

## 目的

`L7-M5-S1` の Capability × Profile と、`L7-M5-S2` の意味適合、`L7-M5-S3` の不足時禁止・明示縮退を、一つの受入実施単位で確認し、証跡と状態を非相殺で集約する規則を定める。Provider、SDK、Harness、Adapter、接続又は試験自動化の方式は定めない。

## 実施単位と適用範囲

実施単位は、`Capability群 × Profile（P-C／P-A／P-N）× 対象操作又はTrigger` とする。条件付きCapabilityはTriggerが成立した実施単位だけを対象とし、Trigger不成立は`非該当`であって成功・失敗・不足ではない。任意AI支援は、支援の有無と明示縮退を確認する対象であり、正本照会・更新等の必須Capabilityを置き換えない。

`P-C`の必須Capabilityと、成立したTriggerに対する条件付きCapabilityは受入の必須対象である。`P-N`は不足時の対象限定禁止・明示結果を確認する必須の否定ケースであり、Capability提供の適合を示す成功には数えない。`P-A`は将来の正規代替に備えた受入可能な任意構成であり、第2AI又は特定Providerの実在接続をMVP必須にしない。

## 必要証跡

| ID | 証跡項目 | 確認する内容 | 非導出事項 |
| --- | --- | --- | --- |
| E-01 | 実施対象・Profile | Capability群、`P-C`／`P-A`／`P-N`、必須・条件付き・任意の分類、対象操作又は成立したTrigger、及びS1の確認状態。 | Provider採用、SDK利用可能又は未検証前提の成立を推測しない。 |
| E-02 | 意味入力・正規経路 | 記録済み正本、明示要求、L2 Guard、L3承認その他S2が要求する意味入力を、AI・UI・Discussion Toolの提供能力と区別して確認した結果。 | 会話、AI記憶、UIローカル状態、自然言語同意又は旧表示を正規経路にしない。 |
| E-03 | 意味結果・正本効果 | 成功、拒否、失敗、結果不明、利用不能、権限不足、正当な空その他L6の記録済み意味結果と、成功時だけのL4正本効果又は非変更を確認した結果。 | 入力到着、AI発話又は画面表示だけから更新・承認・成功を導かない。 |
| E-04 | 同期・冪等性 | 同じ確定Snapshot後の会話・UI同期、部分到達の区別、同一論理要求の最大1業務変更、再送・再同期の既知結果観測又は非変更を確認した結果。 | 部分到達を完全同期にせず、再送・再同期から追加業務変更を導かない。 |
| E-05 | 不足禁止・明示縮退 | `P-N`又は不足した対象で、S3の対象限定禁止、利用不能等の明示結果、任意AI支援の明示縮退及び正本代替禁止を確認した結果。 | 不足を無関係な操作・Sessionへ拡大せず、明示縮退を正本更新又は完全適合へ読み替えない。 |
| E-06 | 前提・実施状態 | Codex前提の確認済み／仮定／未検証、実施の開始・完了又は到達不能の理由、及び下表の実施状態。 | `仮定`又は`未検証`を合格、実装済み又は第2AI接続済みにしない。 |

## 実施順序

1. E-01でCapability、Profile、分類、対象操作又はTrigger及びS1の確認状態を固定する。条件付きCapabilityのTrigger不成立は`非該当`として記録し、意味適合の成功を置かない。
2. E-02で正規経路と意味入力を確認し、E-03でS2の意味結果・Guard・正本効果を照合する。更新は成功確定時だけ、照会・通知・任意AI支援は非変更として確認する。
3. E-04で確定Snapshot、部分到達、再送、競合及び再同期を照合する。同一論理要求の業務変更が最大1回でない、又は同期を確認できない場合は成功・同期済みにしない。
4. Capabilityが不足する`P-N`又は不足ケースでは、E-05でS3の禁止・明示結果・縮退を確認する。必須又は成立TriggerのCapabilityを正規代替なしで実行・成功扱いにした場合は不合格とする。
5. E-06に前提と到達状況を記録して実施状態を置き、必須対象、否定ケース及び任意構成を区別して非相殺集約する。

## 実施状態

| 状態 | 意味 | 集約への扱い |
| --- | --- | --- |
| 未実施 | 実施単位を開始していない。 | 必須対象なら総合合格にしない。 |
| 未検証 | 実施を開始したが、仮定・未検証前提、必要証跡又は意味結果を確認できず、合格・不合格を置けない。 | 合格へ丸めず、必須対象なら総合合格にしない。 |
| 合格 | 当該Profileで必要なE-01〜E-06を確認し、S2の意味適合又はS3の必要な不足禁止・明示縮退を満たす。 | 該当する実施単位の合格としてのみ数える。`P-N`の合格は提供Capabilityの合格を代替しない。 |
| 不合格 | 意味契約、Guard、正本効果、最大1変更、同期、対象限定禁止又は正本代替禁止に反する。 | 他Profile、他Capability又は別結果の合格で相殺せず、必須対象なら総合合格を阻害する。 |
| 非該当 | 条件付きCapabilityのTriggerが不成立で、当該Capabilityを必要とする操作を行っていない。 | 未実施・未検証・合格・不合格に読み替えず、Trigger成立時の証跡を代替しない。 |
| ブロック | 必要な正本確認点、正規経路又は記録済み結果に到達できず、実施を完了できない。 | 合格へ数えず、未実施・未検証・不合格と理由を混同しない。 |

## 非相殺集約規則

- `P-C`の必須Capability、成立したTriggerの条件付きCapability及び全`P-N`否定ケースは、すべて合格の場合だけ総合合格候補とする。これらのいずれかに未実施、未検証、ブロック又は不合格が一つでもあれば総合合格にしない。
- 必須Capabilityの不合格又は未検証を、`P-N`で禁止できたこと、任意AI支援の縮退、別Capability、別Profile又は別操作の合格で相殺しない。`P-N`は不足を隠さないことの確認であって、提供Capabilityの代替ではない。
- 条件付きCapabilityはTriggerが成立した実施単位だけで合否を集約する。Trigger不成立の`非該当`を合格件数へ加えず、Trigger成立時の不足・不合格を別の非該当で相殺しない。
- `P-A`の未実施・未検証又はブロックは、第2AI接続をMVP必須にしないため`P-C`の必須合格を単独では阻害しない。ただし実施した`P-A`で不合格となった場合、その正規代替構成を合格又は適合済みと表示しない。
- 任意AI支援は、提供確認又はE-05の明示縮退を確認した実施単位だけを合格とする。無表示、正本代替又は必須・条件付きCapabilityの不足隠蔽は不合格とするが、適法な不提供・明示縮退は`P-C`の必須合格を単独では阻害しない。任意AI支援の状態は必須実施単位と分けて示す。
- 再実施は新しい実施単位として証跡を残す。過去の未実施、未検証、ブロック又は不合格を削除・上書きせず、再実施だけから旧結果を相殺しない。

## 責務境界

- S1はCapability × Profileと前提状態、S2は正方向の意味適合、S3は不足の否定判定と明示縮退を所有する。本書は実施単位、証跡、状態及び非相殺集約だけを所有する。
- L2は状態・遷移・Guard、L3はActor・承認、L4は正本・Relation・履歴・Undo、L5は提示要件、L6はCapabilityと意味結果を所有する。本書はそれらを実施結果から再定義・変更しない。
- L8はHarness、Provider検出、SDK、Adapter、Tool呼出し、相関、Clock、通信、証跡収集・保存、試験自動化及び実装上の縮退方式を所有する。本書は具体的な実装又は接続方式を選定しない。
