# L7-M3-S2 Undo適用・拒否後の正本／原子性／ライフサイクル整合の合格条件

## 目的と固定入力

本書は、L7-M3-S1の分類・種別・依存パターン別受入Caseに対し、Undo適用又は拒否後の業務正本、全適用／全拒否、L2のライフサイクル整合及びL3の権限・Guard整合を判定する合格条件を定める。

分類はL4-M4-S1、計画の原子性はL4-M4-S2、依存閉包はL4-M4-S3、適用後の論理整合とUndo履歴RelationはL4-M4-S4を入力とする。本書は受入Oracleだけを定め、Undoの操作、API、実行手順、Transaction、Rollback、補償、保存方式又はFixtureを定めない。

## 共通合格Oracle

| 確認対象 | 合格条件 | 不合格時の期待結果 | 境界 |
| --- | --- | --- | --- |
| 適用対象の全体性 | 許可されたUndo計画は、対象ChangeSet、各Event、Entity及びRelationを計画どおり全て適用する。 | 一部Event、一部属性、一部Entity、一部Relation又は一部連動先だけを適用する結果は単独不合格とし、計画全体を拒否する。 | 計画の選択・原子性はL4-M4-S2が所有する。 |
| 対象外の不変 | 対象外のChangeSet、Event、Entity、Relation、別Session及び無関係な時系列後続は、Undoの前後で業務正本として不変である。 | 対象外を変更、追加、削除、補完又はUndo対象へ編入する結果は単独不合格とし、計画全体を拒否する。 | 依存閉包はL4-M4-S3が所有する。 |
| 拒否後の業務正本 | 拒否時は対象を含む業務正本、状態、Decision、親子、現在地、復帰先、履歴及びGuardを変更しない。拒否理由は該当した既存Oracleと整合する。 | 拒否を部分適用、正常完了、履歴削除又は業務ChangeSetとして扱う結果は単独不合格とする。 | 拒否理由の保存・提示方法はL8／L5が所有する。 |
| L2ライフサイクル | 適用後もL2が定める状態組合せ、単一現在地、親子・到達経路・復帰先及び通常進行の不変条件を満たす。 | 状態不整合、孤立、複数現在地、無効な復帰先又はUndoだけによる正常完了・親復帰は単独不合格とし、計画全体を拒否する。 | 状態、完了可否、遷移及び構造意味はL2が所有する。 |
| L3権限・Guard | L3が定めるユーザーの明示Undo要求、基準権限及び全ての該当Guardを満たす。UndoだけでGuardを解除、確定、論点化又は通常進行へ移さない。 | 権限迂回、AI又は暗黙要求、Guard不充足又は暗黙解除は単独不合格とし、計画全体を拒否する。 | Actor、承認及びGuardの成立・解除はL3が所有する。 |
| 成功後の履歴 | 成功時は新Undo Event／ChangeSet及び元対象へのUndo Relationを保持し、元Event、旧内容、新旧Relation、由来及び根拠会話を削除・上書きしない。 | Relation欠落、元履歴削除又はUndo自身・既Undo対象の再対象化は単独不合格とする。 | Event、ChangeSet、現行正本及び履歴RelationはL4が所有する。 |

## 重大単独不合格表

次のいずれも、他のCase又は他の観測結果で相殺しない。一件でも確認された場合は当該計画を不合格とし、成功として集約しない。

| 失敗 ID | 重大失敗 | 適用する判定 | 期待結果 |
| --- | --- | --- | --- |
| F-01 | Event、属性、Entity、Relation又は連動ChangeSetの部分適用 | A-01、A-02 | 計画全体を拒否し、業務正本を不変に保つ。 |
| F-02 | 閉包外変更の取り込み、閉包欠落、孤立又は一意に閉じない分岐 | A-02 | 計画全体を拒否し、推測で閉包を補わない。 |
| F-03 | 対象外のChangeSet、別Session又は無関係な後続への変更 | A-01、A-02 | 計画全体を拒否し、対象外を不変に保つ。 |
| F-04 | 状態不整合、複数現在地、親子・到達経路の破壊又は無効復帰先 | A-04 | 計画全体を拒否し、L2正本を変更しない。 |
| F-05 | Undoだけによる正常完了、親復帰、現在地変更、訂正、再判断、業務上取消、Proposal判断・論点化又はGuard解除 | A-04、A-05 | 計画全体を拒否し、対応するL2／L3許可経路を迂回しない。 |
| F-06 | ユーザー明示要求・L3権限・Guardを満たさない実行 | A-05 | 計画全体を拒否し、AI又は暗黙操作をUndo実行として扱わない。 |
| F-07 | 拒否後の業務正本変更又は拒否理由と既存Oracleの不整合 | A-03 | 拒否を業務変更にせず、実行前正本を維持する。 |
| F-08 | 新Undo ChangeSet／Undo Relationの欠落、元履歴・旧内容・由来の削除又は再Undo | A-06 | 成功を認めず、元履歴を非削除で保持する。 |

## 責務境界とTask固有Review

- 本書はL7-M3-S1の受入Caseを、全適用／全拒否、対象外不変、L2／L3整合及び重大単独不合格で判定する。例外変更・現行／旧結果・履歴・由来の詳細な受入条件はL7-M3-S3、実施手順・証跡・合否集約はL7-M3-S4が所有する。
- L2は状態・構造・完了・遷移、L3はActor・承認・Guard、L4は正本・Event・ChangeSet・依存・履歴・Undo Relation、L5は提示、L6は操作・API・Capability、L8は実装・Transaction・Rollback・補償・保存・Fixtureを所有する。
- Redo、時間制限、物理Rollback、補償、履歴削除又は新しい状態・遷移・ChangeSet分類を追加しない。
- [x] 全適用、対象外不変及び拒否後の業務正本不変を判定した。
- [x] L2の状態・親子・現在地・復帰先・通常進行とL3の権限・Guardを判定した。
- [x] 部分適用、孤立、無効復帰先、権限迂回及び履歴不整合を重大単独不合格とした。
- [x] S3／S4及びL2〜L8のOwner境界を確認した。
