# L7-M3-S4 可逆性受入の実施・証跡・合否集約規則

## 目的と固定入力

本書は、L7-M3-S1のUndo受入Case、L7-M3-S2の正本・原子性・L2／L3整合Oracle、及びL7-M3-S3の例外変更・履歴・由来Oracleを、一貫した受入実施、証跡及び合否集約へ接続する。

本書は実施順、証跡、未実施／合格／不合格／無効／ブロック及び非相殺集約だけを定める。実測の実施、試験Fixture、操作UI、API、保存形式、Clock、Transaction、Rollback又は自動化方式は定めない。

## 実施単位と事前固定

- 一つの**受入実施**は、S1の一つのCase又は展開Caseについて、前正本、依存、L2／L3入力、操作試行、再照会及び証跡照合を一組で扱う単位とする。
- 一つの**受入サイクル**は、同じS1 Case／展開Case、S2・S3の基準版及び対象正本を固定した受入実施を集約する単位とする。別Case、別分類、別依存形状、別正本又は別基準版で代替しない。
- 実施前に、Case ID、対象ChangeSet／連動計画、前正本、依存根拠、期待する成功又は全拒否、該当するS2・S3判定ID及び再試験なら元実施との関係を固定する。
- 不可分類又は非Undo対象は、成功を期待するCaseへ読み替えない。拒否Caseの試行は業務変更を発生させず、S2／S3が求める不変正本と操作試行証跡を確認する。

## 受入実施の手順

| 手順 | 実施で確認すること | 合格に導かないこと・Owner |
| --- | --- | --- |
| `P-01` 事前状態 | L4-M2の記録済み現行正本、対象ChangeSet、対象外、依存及びL2／L3の該当入力を再照会する。 | 履歴順、表示又は会話近接から前正本を選ばない。正本選択はL4が所有する。 |
| `P-02` 操作試行 | S1のActor・Guard入力に対応する一回のUndo試行を記録する。 | Actor・承認・Guardを定義又は解除しない。Undo操作はL6、権限はL3が所有する。 |
| `P-03` 結果再照会 | 操作後に現行正本、対象外、L2構造・状態、L3 Guard及び適用又は全拒否の結果を再照会する。 | 試行の成功表示、応答又は時刻だけで適用済みと推測しない。 |
| `P-04` 履歴・由来照合 | 成功時は新Undo Event／ChangeSet、Undo Relation、元Event・旧内容・新旧Relation及び根拠会話を確認する。拒否・失敗・no-op時は、これらを業務変更履歴に作らず試行結果・理由と区別する。 | 訂正、再判断又は業務上取消をUndoへ、又はUndoをそれらへ置換しない。詳細はS3が所有する。 |
| `P-05` Case判定 | S2及びS3の全該当Oracle、成功又は全拒否の期待及び証跡の完全性を照合する。 | 部分適用、孤立、L2／L3不整合又は履歴削除を他の確認結果で相殺しない。 |

## 実施状態と証跡

| 状態 | 定義 | 集約への扱い |
| --- | --- | --- |
| 未実施 | 固定した受入実施を開始していない。 | 合格・不合格・無効・ブロックへ読み替えない。 |
| 合格 | P-01〜P-05の該当確認点と必要な証跡を確認でき、S1〜S3の全該当Oracleを満たす。 | 当該Caseの合格実施として記録する。 |
| 不合格 | 必要な確認はできたが、S1〜S3のOracle、全適用／全拒否、不変条件又は履歴・由来条件の一つでも満たさない。 | 当該Caseを不合格として記録する。 |
| 無効 | 操作又は確認の実施記録はあるが、必要な正本・履歴・由来又は入力を確認できず、合否を判定できない。 | 合格・不合格又は拒否へ推測変換せず、確認不能な項目と理由を残す。 |
| ブロック | 必要な入力、対象正本又は確認経路を利用できず、実施を開始又は継続できない。 | 未実施・無効・不合格へ置き換えず、原因を残す。 |

各受入実施には、少なくとも次の証跡を対応付ける。識別子、保存先、検索、表示又は収集方式は定めない。

| 証跡項目 | 内容 |
| --- | --- |
| 実施参照 | 受入サイクル、受入実施、Case／展開Case、再試験関係を区別する参照。 |
| 固定入力 | S1 Case、対象ChangeSet／連動計画、前正本、依存根拠、期待結果、S2・S3の該当判定ID。 |
| 操作試行 | L3の明示Actor入力、該当Guardの確認結果及びL6の試行結果。 |
| 再照会結果 | 操作後の現行正本、対象外、L2状態・構造、L3 Guard及び全適用又は全拒否の確認結果。 |
| 履歴・由来 | 成功時のUndo Event／ChangeSet・Undo Relation・元履歴・根拠会話、又は拒否・失敗・no-op時の分離した試行理由。 |
| 判定・非相殺根拠 | 状態、該当した不合格Oracle、又は全該当Oracleを満たした根拠。 |

## 非相殺集約と再試験

- 集約は固定したCase／展開Caseごとに独立して行う。可能／条件付き／不可、単一／複合、依存なし／直列／分岐、成功／拒否を平均、代替又は相殺しない。
- S2の部分適用、対象外変更、L2不整合、L3権限迂回、又はS3の現行推測・履歴削除・由来欠落・4種混同は重大単独不合格とする。一件でも確認したCaseを他Caseの成功で合格へ戻さない。
- 一つの受入サイクルは、該当する全受入実施が合格のときだけ合格とする。不合格が一件でもあれば不合格とし、未実施、無効又はブロックが残る場合は合格と確定しない。
- 無効又はブロックの原因を解消した後は、同じ固定Case・入力に対する新しい受入実施を追加できる。元の実施、状態、原因及び証跡を削除又は置換しない。
- 不合格後に要件、正本、実装又は基準が変わった場合は、新しい受入サイクルとして扱う。前の合格を流用せず、再試験を不合格の上書きにしない。

可逆性受入整合Gateへは、各Caseの集約状態、重大単独不合格の個別根拠、適用したS1〜S3基準及び証跡参照を渡す。実測を行ったこと、実施回数、対象Caseの増減又はGate通過そのものは本書単独では確定しない。

## 責務境界とTask固有Review

- S1は分類・Case・依存形状、S2は正本・原子性・L2／L3整合、S3は例外変更・履歴・由来を所有する。本書はそれらを実施・証跡・状態・集約へ接続する。
- L2は状態・構造・完了・遷移、L3はActor・承認・Guard、L4は正本・Event・ChangeSet・Relation・履歴・由来、L5は提示、L6はUndo操作・API・照会、L8はFixture・実装・Transaction・Rollback・保存・試験方式を所有する。
- Redo、時間制限、物理Rollback、補償、履歴削除、新しいChangeSet分類又は実測必須条件を追加しない。
- [x] 事前状態、Undo試行、正本再照会、履歴・由来確認及びCase判定の順を定義した。
- [x] 未実施／合格／不合格／無効／ブロックと、必要な証跡を分離した。
- [x] 重大失敗を非相殺とし、再試験が旧実施を上書きしない規則を定めた。
- [x] S1〜S3、L2〜L6、L8及び可逆性受入整合Gateとの責務境界を確認し、未解決の契約差異又はTBDを残していない。
