# L7-M4-S5: 復元受入の実施・証跡・非相殺集約規則

## 目的

正常終了前後の正本、FR-020の7対象、参照関係、復元後の通常進行再開又は安全停止を、同一の受入実施単位で証跡化し、未実施・合格・不合格・無効・ブロックを混同せず非相殺で集約する規則を定める。

履歴、Event／ChangeSet、由来及びUndoは第8の復元対象でなく、7対象と現行正本を照合する横断証跡として扱う。

## 実施単位と必要証跡

実施単位は、`L7-M4-S1` の対象Session、正常終了前確定点、同じ対象Sessionを復元した後の結果から成る。各実施単位は次を対応付けて記録済みの証跡として確認できる。

| ID | 証跡項目 | 確認する内容 | 非導出事項 |
| --- | --- | --- | --- |
| E-01 | 終了前正本 | 正常終了前確定点における7対象の値あり／正当空／欠落、対象Session及び必要な既存正本・Relation。 | 欠落を空又は値へ補完しない。 |
| E-02 | 復元後正本 | 同じ対象Sessionの復元後に、7対象ごとの現行正本と値あり／正当空／欠落を確認した結果。 | Projection、古いUI又は別Sessionを正本にしない。 |
| E-03 | 関係・履歴横断照合 | 階層・経路・現在地・復帰先・派生元・Session所属、Decision等、Event／ChangeSet、根拠会話、旧内容及びUndoをS3 Oracleに対応付けた結果。 | 履歴等を第8対象にせず、旧値・時系列だけから現行を選ばない。 |
| E-04 | 正常再開又は安全停止 | S2のR-01〜R-06が成立した通常進行Anchor、又はS4のS-01〜S-04による停止理由・影響範囲・次に必要な確認。 | 復元・再同期だけから業務変更、Guard解除又は修復成功を導かない。 |
| E-05 | Session分離 | 対象Sessionと無関係Sessionの境界、混入の有無、継続を確認した無関係Sessionがある場合の独立境界。 | 無関係Sessionを影響Sessionの補完又は相殺に使わない。 |

## 実施状態

| 状態 | 意味 | 集約への扱い |
| --- | --- | --- |
| 未実施 | 対象Session・確定点・復元結果を対応付けた実施単位をまだ開始していない。 | 合格にも不合格にも数えず、必須なら総合合格にしない。 |
| 合格 | E-01〜E-05が確認でき、S2の正常再開、又はS4に従う安全停止・非再開を根拠とともに確認できる。 | 必須条件の合格候補とする。 |
| 不合格 | 7対象欠落、Session混入、S3不合格、又はS4の停止条件に反して通常進行・更新を行ったことを確認できる。 | 同一又は別Sessionの合格で相殺せず、総合合格を阻害する。 |
| 無効 | 実施は開始したが、必要な終了前後の記録又は照合根拠を確認できず、S2／S3／S4のいずれにも妥当な判定を置けない。 | 合格へ丸めず、再実施・除外の可否は後続Ownerへ渡す。 |
| ブロック | 必要な記録済み入力又は確認経路に到達できず、実施を完了できない。 | 合格へ数えず、理由を未実施・無効・不合格と混同しない。 |

## 実施順序

1. 対象Session、正常終了前確定点及び適用Profileを固定し、E-01として終了前正本を確認する。
2. 同じ対象Sessionを復元した後、E-02として7対象の復元後正本を確認する。E-01又はE-02の必須証跡が不足する場合は、S4の分類に従う安全停止又は無効・ブロックとして記録し、通常再開へ進めない。
3. E-03として関係・履歴横断照合を行い、S3のO-01〜O-08に不合格があればS4の安全停止へ分岐する。照合を省略して通常再開又は合格にしない。
4. S3に不合格がなく、S2のR-01〜R-06が成立する場合はE-04に通常進行Anchorを記録する。S4に該当する場合は、停止理由、影響範囲及び次に必要な確認をE-04に記録し、通常進行へ接続しない。
5. E-05としてSession分離及び無関係Sessionの独立継続条件を確認した後、E-01〜E-05の証跡に基づいて実施状態を置き、非相殺集約する。

## 非相殺集約規則

- 必須の実施単位は、すべてが合格である場合だけ総合合格候補とする。未実施、無効又はブロックが一つでもある場合は総合合格を出さない。
- 不合格は、別のSession、別の保持期間、別の規模、別の環境又は無関係Sessionの合格で相殺しない。停止違反、混入、欠落補完、現行旧逆転及び参照閉包破損を軽減値へ変換しない。
- S4により影響Sessionを安全停止したことは、正常再開の合格ではない。停止理由・影響範囲・非推定及び無関係Sessionの独立継続条件を満たしたかを、当該停止ケースの証跡として別に確認する。
- 再実施は新しい実施単位として記録する。過去の未実施・無効・ブロック又は不合格の証跡を削除せず、再実施だけから旧結果を置換しない。

## 責務境界

- S1は対象・確定点・Profile、S2は正常再開、S3は正本・参照閉包不合格、S4は安全停止を所有する。本書は実施単位、証跡、状態及び集約だけを所有する。
- L2〜L4の状態・Actor・正本・Relation・履歴・Undo、L5の提示、L6の操作・APIを再定義しない。具体的な収集方法、保存、Snapshot／Replay、DB、Transaction、障害復旧及び欠損補正はL8が所有する。
